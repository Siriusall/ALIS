# ALIS

ALIS 是一个面向沪深 A 股的个人研究与模拟交易系统。它把市场数据、公司研究、因子、模型、策略、组合优化、模拟成交、独立账本、绩效归因和自动研究连接成一条可以审计、回放和持续演进的闭环。

ALIS 不是荐股页面，也不是把若干模型分数相加后直接下单的脚本。系统真正管理的是完整的决策因果链：某项数据何时被观察到，哪些证据参与判断，为什么产生某个动作，目标权重如何形成，订单为什么成交或被拒绝，现金和持仓如何变化，以及这次判断最终是否创造了成本后的超额收益。

> ALIS 当前只用于个人研究和模拟交易，不接入实盘，不提供证券投资建议，也不承诺任何收益。

## 1. 系统目标与原则

ALIS 的第一目标是验证并提升策略有效性，第二目标是控制风险、消除回测失真并保证长期稳定运行。

最终形态是模拟交易范围内的无人值守闭环：系统自行维护数据，生成和验证因子、模型与策略候选，在隔离账户中观察候选，完成样本外检验和治理审计，晋升真正有效的版本，并在失效后自动回退。项目所有者通常只需查看每日计划、账户收益、候选进展和明确异常。

系统坚持以下原则：

- 真实可得的数据优先于事后看起来完整的数据。
- 成本后、可成交的收益优先于理想化回测收益。
- 每项生产行为都必须追溯到冻结版本和冻结证据。
- 研究失败是有效结果，不能靠反复调参、重复使用同一测试集或放宽门槛掩盖。
- 程序错误可以原地修复；策略效果调整必须生成新版本和新实验。
- LLM 可以解释和提出候选，但不能生成成交、批准自己或绕过安全合同。
- 页面是只读控制台，读取页面不能触发交易或改变生产版本。

```text
        买入 / 加仓 / 减仓 / 退出 / 持有 / 防御
                       │
                       ▼
      CVaR / HRP / 等权 / 保持持仓的组合竞赛
                       │
                       ▼
           T 日冻结正式计划与完整版本清单
                       │
                       ▼
         T+1 精确行情门、模拟执行与原子落账
                       │

        账户曲线、收益归因、复盘与异常审计
                       │
                       ▼
    因子 / 模型 / Controller / 策略新候选
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
       立即建立隔离账户      正式研究资格链
       持续真实日观察       OOS → 密封集 → Shadow
             └─────────┬─────────┘
                       ▼
              治理审计 → 晋升或淘汰
```

整套系统可以分成七个相互约束的平面：

1. 数据平面：回答“系统当时究竟知道什么”。
2. 研究与信号平面：回答“哪些信息可能具有收益含义”。
3. 策略控制平面：回答“面对当前持仓应该采取什么动作”。
4. 组合与风险平面：回答“每个资产应该配置多少”。
5. 执行与账本平面：回答“订单能否真实成交以及钱和仓位如何变化”。
6. 评价与进化平面：回答“这个版本是否真的有效，能否进入生产”。
7. 运行与审计平面：保证任务、租约、恢复、版本和异常长期一致。

## 3. 核心技术组成

- FastAPI 后端：业务 API、调度入口、交易安全门和只读控制台数据服务。
- React/Vite 前端：展示今日决策、账户、研究、进化、数据和审计证据。
- PostgreSQL 业务库 `alis_sim`：策略、版本、计划、成交、账户、账本、候选、任务和评价证据。
- PostgreSQL 数据平台库 `alis_data`：原始数据、标准化快照、观察时钟、覆盖率、质量、水位和研究数据资产。
- Redis：缓存、运行日志、协调信号和部分任务通信。
- 持久任务系统：承载正式 OOS、模型训练、数据补全和其他可恢复长任务。

生产语义只建立在 PostgreSQL 双库上，不允许静默回退到 SQLite。数据平台保存外部世界及其可得性，业务库保存系统基于这些数据作出的判断和账户变化。

## 4. 当前运行节点与系统职能

生产系统当前由四个相互隔离的运行节点组成。下表只描述逻辑角色，不包含云厂商、主机名、地址、端口、账号、域名、凭据、目录或网络配置。

| 脱敏节点 | 核心定位 | 承载组件 | 主要系统职能 | 明确不承担 |
| --- | --- | --- | --- | --- |
| 节点 A：应用与控制面 | 对用户提供系统入口，并拥有日常业务调度权 | 生产前端、API、缓存与协调服务、日更调度器、模拟交易调度器、自治调度器、发布与健康检查 | 展示控制台；生成正式计划；触发 T+1 执行；协调数据日更、账户复盘、任务入队、版本发现和异常汇总 | 不保存 PostgreSQL 主数据；不长期执行重型 OOS、训练或大规模研究任务；不运行第二个共享研究 Worker |
| 节点 B：数据与状态中心 | 保存全系统权威数据和事务状态 | PostgreSQL 业务库 `alis_sim`、数据平台库 `alis_data`、数据库结构修订与访问控制 | 保存原始数据版本、标准化快照、PIT 证据、策略与模型版本、任务租约、计划、成交、账户、账本和审计记录；提供跨节点事务一致性 | 不对外提供前端或业务 API；不生成计划；不执行研究任务；不承担云端数据库备份副本 |
| 节点 C：控制任务 Worker | 消费轻量、短周期和兼容性研究任务 | 独立 Evolution Worker，固定领取 `control` 任务池 | 执行轻量治理、任务编排辅助、兼容旧任务和不适合占用应用进程的后台工作；通过数据库租约防止重复领取 | 不提供 API、前端或缓存服务；不运行日更调度和模拟交易；不直接修改正式账户；不领取重型 `research` 池任务 |
| 节点 D：重型研究 Worker | 为计算密集型研究提供独立资源 | 独立 Research Worker，固定领取 `research` 任务池 | 执行因子研究、模型训练、策略迭代、正式 OOS、候选验证和其他可检查点恢复的重任务 | 不提供 API、前端或缓存服务；不生成或执行正式调仓计划；不操作生产模拟账本；不承担数据库备份 |

四个节点不是四套独立系统。它们共享同一套业务合同和权威数据库，通过任务池、数据库租约、检查点和版本清单协作：

```text
用户
  │
  ▼
节点 A：应用、控制台和唯一日常调度入口
  │                  │
  │ 读写权威状态       │ 创建持久研究任务
  ▼                  ▼
节点 B：双库中心 ◀── 节点 C：control Worker
  ▲                  节点 D：research Worker
  └────结果、心跳、租约和检查点────┘
```

### 4.1 职责边界

- 正式计划的生成和模拟执行只由节点 A 的确定性调度链发起，研究 Worker 没有交易权限。
- 节点 C 和节点 D 都从节点 B 的持久任务表领取任务，但各自只能领取所属任务池。
- 任务租约、心跳和检查点保存在节点 B；某个 Worker 中断后，只能按租约恢复规则继续任务。
- 节点 A 内置的共享 Evolution Worker 处于关闭状态，避免与外部 Worker 重复消费。
- 研究结果必须写回权威证据表并经过生产资格门，不能由 Worker 直接激活模型或 Champion。
- Redis 只承担缓存和协调，权威任务、计划、成交和账本状态均以 PostgreSQL 为准。
- 数据库备份不放在上述云端运行节点，采用独立的本机备份边界，避免与生产故障域混在一起。

### 4.2 节点故障的影响范围

| 故障节点 | 直接影响 | 系统应保持的安全行为 |
| --- | --- | --- |
| 节点 A | 控制台、API、调度和模拟执行暂停 | 不产生新计划或成交；数据库、历史证据和已保存任务保持不变；恢复后先做启动对账 |
| 节点 B | 全系统权威数据暂不可读写 | 所有正式决策、执行和任务状态更新失败关闭；不得回退到本地临时数据库继续交易 |
| 节点 C | 轻量控制任务停止推进 | 已有任务保留租约和检查点；不影响已冻结计划的确定性执行链；恢复后按租约规则续跑 |
| 节点 D | 重型研究和 OOS 停止推进 | 日常正式决策与模拟交易可继续；候选不得因研究节点离线而跳过验证或获得生产资格 |

这种拆分把交易控制权、权威数据和研究计算分开：研究可以消耗大量资源或失败，但不能拖垮面向用户的 API、篡改正式账户或绕过生产安全门。

## 5. 数据平面

### 5.1 数据资产

数据平台覆盖股票、指数和 ETF 日行情，估值、市值和换手，复权因子、涨跌停和停牌状态，财务报表与披露日期，业绩预告、快报和一致预期，回购、股东增减持、质押、分红送股，公告、新闻、主题、行业状态、公司收入暴露、基准序列，以及部分宏观、期货和行业研究数据。

每个数据域还维护覆盖率、水位、失败请求、质量检查、来源表现和可恢复状态。

### 5.2 原始记录与标准化快照

每次外部请求不仅保存最终值，还保存来源、参数、响应内容、内容哈希、请求状态和观察时间。相同经济数据的不同返回版本不会直接互相覆盖，而是形成可追踪的原始版本。

标准化层从原始版本中选择符合当前合同的记录，生成稳定消费快照。例如全市场日截面会统一证券代码、价格、成交量、金额、估值、涨跌停和交易状态。原始记录用于追溯和重建，标准化快照用于研究与决策。

### 5.3 点时可用性与四类时间

避免未来数据泄漏是 ALIS 最核心的设计之一。系统区分：

- 经济时间：数据描述哪一天、报告期或事件。
- 发布时间：数据源声称何时公开。
- 观察时间 `observed_at`：ALIS 实际收到记录的时间。
- 决策截止时间：某次决策允许使用信息的最晚时刻。

市场日期不等于可得时间。一条属于 T 日、但在 T 日 16:00 才获取的数据，不能伪装成 15:00 已经可用。正式证据要求带明确时区的真实观察时间；缺少观察时钟、来源不可信或晚于截止时刻的记录会被排除。

生产信号默认以 T 日 15:00 为截止。T+1 开盘价只能用于模拟成交，不能回流为 T 日信号特征。

### 5.4 完整性硬门

最新正式决策至少要求同日、完整且通过点时检查的：

- `daily`
- `daily_basic`
- `stk_limit`
- 标准化当日股票快照

不同用途使用不同合同。正式 OOS 固定要求连续 1,537 个交易日的 `daily + daily_basic + stk_limit + adj_factor + 标准化截面 + 观察时间`。执行已冻结计划时，只检查 T+1 实际订单所需的开盘、前收盘、涨跌停、停牌、成交量和 ETF 精确日线，不会因无关估值字段晚到而阻断旧计划。

空结果也有明确语义：合法无数据、上游尚未发布、权限不足、接口失效和真实请求失败不能混为一类。无法取得的数据必须报错或保留为不可观测，不能伪造为完整。

### 5.5 多源发布发现与竞速

收盘数据并不在固定时刻同时发布。ALIS 使用发布探针周期性检查多个来源，哪个来源先返回合格数据，就优先从该来源取得完整切片，而不是无限等待单一主源。

“先返回”仍必须通过日期、证券范围、字段、行数、全市场覆盖率、前后日连续性和重叠样本对账。系统同时记录来源性能、失败次数、熔断状态、批次检查点和断点续跑进度。

TuShare 是主要结构化来源；腾讯、东方财富等在特定数据域中承担受约束的备用角色。备用源只补真实缺口，不覆盖已经合格的主源记录。

## 6. 研究平面

研究层不直接发订单，而是形成可证伪、可冻结、可追踪的收益假设。

系统的证据分工是：叙事解释潜在空间，资金持续性确认认可程度，价格结构与相对强度决定时点，基本面、估值与盈利预期决定持有期限，市场状态决定整体风险预算，交易成本、拥挤度和流动性决定纸面机会能否转化为收益。单一新闻、叙事、资金流或模型分数均不能独立触发买入。

公司研究覆盖财务质量、成长、现金流、估值、预期、事件和风险；行业研究覆盖行业状态、景气、政策、供需、价格、产销和公司行业映射。

研究证据区分可观测和不可观测。公司产能、平台留存、同店增长等指标如果缺少直接证据，不会用财报代理字段冒充。PDF、网页和 OCR 提取只能形成低优先级候选，必须保存原文、页码、单位、哈希和对账状态，在结构化来源确认前不能进入生产信号。

投资逻辑卡片记录收益来源、支持证据、持有周期、退出条件和禁止条件。后续事实会形成验证记录，但不会覆盖当时的原始判断。

## 7. 因子平台

统一因子注册表管理因子定义、版本、依赖、点时规则、物化结果和评价证据。主要类别包括：

- 量价：成交量、成交额、换手和涨跌幅。
- 趋势：5日和20日动量等。
- 波动与风险：20日波动率、市场 beta 等。
- 市值与估值：流通市值、总市值、PE、PB。
- 交易状态：ST、停牌、涨停和跌停。

物化、选股、训练、回测、重放和每日决策共享同一注册版本，避免“研究时一个公式、生产时另一个公式”。

评价包括 IC、Rank IC、分组收益、成本后增量、稳定性和泄漏审计。候选因子从登记开始独立积累未来评价截面；历史回测不能替代至少 20 个真实未来截面的观察。交易约束因子长期参与风控，但不会因为 IC 较低而被当作 Alpha 因子淘汰。

## 8. 模型层

模型把复杂数据压缩成结构化信号，但没有直接交易权限。系统设计的模型族包括：

- `market_regime_hsmm_v1`：市场状态及持续时间。
- `medium_horizon_lambdarank_v1`：中期股票相对排序。
- `capital_persistence_multitask_v1`：资金持续性和衰减。
- `leader_lambdarank_v1`：龙头排序。
- `event_impact_assessor_v2`：已发生事件的条件影响、定价程度及延续/反转概率。
- `narrative_transition_multitask_v1`：叙事生命周期状态。

模型注册表保存训练任务、版本、产物、数据窗口、指标、验证状态、生产资格和激活状态。数据库里存在模型版本或 `is_active` 标记，并不自动赋予生产权限；融合入口会重新检查完整资格合同。

当前五个业务模型均没有生产激活版本，正式选股主要由生产因子与透明规则承担。模型只有完成任务原生 OOS、同任务强基线、冻结策略 A/B、至少 20 个真实未来交易日观察和最终治理审计后，才能取得排序或准入影响力。

失败模型保留研究价值和证据，但不能影响新决策。历史冻结计划可以按版本 ID 回放旧产物，这只是历史可重现能力，不代表旧模型重新上线。

## 9. 统一选股与预期收益

研究和模型输出汇入统一股票选择链，完成股票池与交易资格过滤、数据和点时检查、基础因子评分、合格模型融合、行业/主题/事件增强、预期收益与成本表达，以及当前持仓和新候选的同口径比较。

模型没有生产资格时，其权重会归还基础因子和确定性规则，而不是保留空壳分数。研究增强缺失时可以明确降级为中性；行情和交易状态等硬数据缺失时必须阻断正式计划。

## 10. StrategyController

StrategyController 是信号与组合之间的策略总控。它根据当前持仓输出统一动作：

- `buy_candidate`：新建候选仓位。
- `add_position`：已有持仓加仓。
- `reduce_position`：降低风险或部分兑现。
- `sell_exit`：退出失效持仓。
- `hold`：保持当前仓位。
- `defensive_switch`：切换到合格防御资产。

每个动作冻结触发模型或规则、原因、预期收益来源、风险预算、持有周期、退出条件、禁止条件、数据状态和 Controller 版本。

这种设计将“信号强弱”和“账户动作”分开。同一个正向信号，对空仓账户可能意味着买入，对已有重仓账户可能只是持有；预期改善不足以覆盖成本时，应优先保持当前持仓。

## 11. 组合优化与风险

Controller 给出动作义务和候选集合后，组合层计算目标权重。ALIS 不使用固定五仓比例，也不为满足标签配额强行买入。功能仓只用于解释和归因。

权重综合预期收益、经验 CVaR、相关性、费用和滑点、换手、拥挤度、集中度、流动性、当前持仓和现金。系统在同一截面比较经验 CVaR、等权、HRP 和保持当前持仓；只有成本后改善越过硬门才切换。主优化失败时降级到 HRP，再失败则保持持仓。

始终保留的安全约束包括禁止负权重、融资和现金透支，不得超卖，满足股票与 ETF 最小交易单位，停牌/涨跌停/异常资产不得违规新增，单笔订单不能超过流动性容量，并遵守冻结的单资产和组合风险合同。

正常交易日以充分利用模拟资金为目标；股票机会不足时在合格 ETF 和防御资产中寻找替代。只有数据、市场、账户或交易单位等硬故障才允许零成交，并必须留下证据。

## 12. 正式计划与 T+1 执行

### 12.1 T 日冻结

普通交易日以 T 日收盘完整数据形成正式调仓计划。计划是不可变执行合同，包含信号日期、数据截止、执行日期和精确时刻、目标权重、冻结整手数量、动作理由、风险预算、费用和滑点，以及数据、因子、模型、Champion、Controller、执行合同和系统发布版本。

计划保存完整合同哈希。同一信号日一旦进入 `planned` 就被冻结；后来到达的研究证据不能改写它，新逻辑只能作用于下一份计划。

### 12.2 T+1 精确数据门

到达冻结执行时刻后，执行器只审计实际订单需要的 T+1 数据：股票开盘、前收盘、涨跌停、停牌/成交状态，以及相关 ETF 的完整 OHLC、成交量和成交额。

数据未发布时，探针按冷却周期检查多源数据。完整后由唯一执行器领取计划；仍不完整则明确保留缺口，不能把缺失汇总成健康。如果自然日越过执行日，计划进入 `missed_execution_window`，禁止用后来补到的数据跨日伪造成交。

### 12.3 原子成交

执行层处理买卖方向、整手数量、费用、滑点、现金、最大可卖数量、停牌、涨跌停、流动性拒单、防重复执行和订单 UID。

买入的现金扣减、成交和持仓增加在同一事务提交；卖出同样原子提交。成交与任务确认之间中断时，计划会被隔离等待账本复核，不能简单重放造成重复成交。

## 13. 模拟账户与独立账本

生产模拟账户以固定本金、逐笔成交、费用、分红送股和显式迁移调整为唯一资金来源。系统每天从这些不可变事件独立重算现金、持仓和权益，再与当前账户投影对账。

账本会发现现金或持仓漂移、重复成交、超卖、透支、成交未绑定计划，以及公司行动重复或漏记。审计只能报告问题，不能为了对齐数字而自动改账；出现漂移时，新自动成交会被阻断。

分红送股按股权登记日冻结资格，在派息日增加现金、除权日增加数量。无分红记录可以是合法空结果，系统会留证和节流。

账户曲线使用精确交易日行情估值。历史缺少持仓 OHLC 时应补真实行情或明确标记，不能用成本价、未来价格或研究用复权序列冒充。

## 14. Champion、Challenger 与隔离账户

唯一 Champion 策略包 `alis_production_strategy` 冻结选股公式和因子、Controller、获准模型、组合方法、风险预算、执行和成本合同。每日计划和历史重放默认读取这个完整包，而不是让各模块临时选择版本。

Champion 正式 OOS 失败会形成长期有效性告警，但不会自动把模拟账户永久锁成只能减仓；日常交易仍受当日数据、Controller、组合、执行和账本安全门约束。

新模型或策略候选创建后即可进入隔离模拟观察，不必先通过所有研究门才允许接触真实交易日环境。这样能尽早暴露无信号、不可成交、换手过高、费用吞噬、行情依赖和风险暴露问题。

“立即观察”不等于“立即生产”。候选独立记录初始现金、每日权益、持仓、决策、订单、成交、费用、拒单、点时合同和版本哈希。候选账户不能读写正式账户，不能继承旧版本成绩，也不能通过页面操作获得生产权限。任何效果调优都必须形成新候选和新账户。

## 15. OOS、密封集与晋升

评价不仅看收益，还看最大回撤、换手、费用、成交率、拒单率、市场/行业/风格暴露、分窗口稳定性，以及相对 Champion 和沪深300的成本后增量。

正式 Purged Walk-Forward OOS 使用训练、隔离、验证、embargo 和测试滚动窗口。每窗固定数据截止、Champion、Controller、成本协议和候选版本。正式比较要求窗口完整、候选真实消费并生效、成本后改善、多数窗口胜出、配对区块 bootstrap 下界通过，并使用 Deflated Sharpe Ratio 校正反复试验产生的选择偏差。

同一批测试窗口被多次查看后只能保留诊断价值，不能换参数或随机种子后继续把同一批窗口宣称为全新 OOS。

通过公开 OOS 和统计门的候选才可一次性消费密封历史保留集。详细收益对候选生成、研究代理、失败归因和前端不可见，只返回通过/失败和合同哈希。数据 126/126 天就绪不代表允许提前查看。

随后候选还需至少 20 个真实未来交易日和足够有效调仓日。Shadow 使用非重叠日权益，要求配对超额收益 bootstrap 下界大于零。全部门通过后先标记 `production_eligible`，再由确定性治理流程晋升。晋升生成新 Champion，旧版本和旧证据永久保留；新版本在冷却期内持续监控，失效时自动回退。

## 16. 自进化系统

自进化不是不受约束地修改自己，而是在固定安全合同内完成“发现问题—提出有限候选—验证—观察—晋升或淘汰”。

自治职责覆盖数据完整性和失败治理、因子物化与未来评价、模型训练故障分类、Controller 和策略候选、组合方法竞赛、成本校准、公司行动、账本、绩效复盘、OOS、密封集、Shadow、晋升和回退。

每个问题族限制试验次数和模板数量，避免无限调参。瞬时网络或资源故障可以有限重试；明确数据缺口委托统一补数；代码合同、权限、未知接口和业务口径错误必须停止循环并升级异常。

## 17. 持久任务、租约与恢复

长时间研究运行在持久任务系统中。任务保存状态、检查点、尝试次数、租约所有者、心跳、错误证据和结果。正式 OOS 逐窗口保存检查点，重启后从未完成窗口继续。

租约和心跳防止多 Worker 重复领取。只有租约过期、为空或同机原进程确认死亡时才允许恢复。取消会原子写入终态并清理租约，迟到 Worker 不能覆盖取消状态。

自治同步步骤有时间预算。超时会明确记录为 `timed_out`，总线继续其他步骤；原线程退出前同名步骤不能重入。确定性异常不能被解释层覆盖成健康。

## 18. LLM 的角色与边界

LLM 是受约束的研究助手，不是交易决策器。

研究代理读取冻结复盘证据，提出 `factor / model / strategy / data` 四类假设。治理层检查引用、重复性、白名单和证据，再路由成普通研究任务。提案不能直接改变因子、模型、Champion、计划或成交。

数据运维代理只能在预定义动作中建议有限重试、关闭确认下线的旧请求、委托硬数据修复或升级外部依赖。真正可执行的请求 ID、分类、次数和批量上限由确定性代码重新计算。LLM 不能执行任意 SQL、Shell、密钥修改、历史覆盖或质量门放宽。

LLM API、JSON 输出或 Token 预算不可用时，核心数据、决策、执行和账本链路必须继续运行。

## 19. 系统版本与证据冻结

ALIS 同时管理代码版本和业务版本。正式决策冻结统一版本清单，包括数据截止和 PIT、因子绑定、生产模型、Champion、Controller、组合与风险、成本、执行合同、数据库结构修订和系统发布清单。

系统发布中心维护组件依赖和兼容性。运行代码、数据库结构、关键合同和活动发布不一致时，会阻断新的自动执行，而不是继续使用无法解释的混合版本。

历史计划永远按自己的冻结版本读取。当前代码只能在执行合同兼容时执行旧计划，不能用当前研究结果重新解释或修改旧计划。

## 20. 健康与状态语义

ALIS 区分“进程活着”和“业务可以交易”：

- 基础健康：API、双库、Redis、调度器和运行组件。
- 数据 readiness：最新截面和长期硬数据是否满足用途合同。
- 交易 readiness：计划、精确执行数据、账本和执行链是否允许动作。
- 研究状态：候选、模型和长期评价是在运行、失败还是等待样本。

历史研究失败、观察样本不足和当天交易硬阻断不是同一件事。常见状态包括：

- `planned`：正式计划已冻结，等待精确执行时刻。
- `executing`：唯一执行器已领取，正在原子处理。
- `executed`：计划完成并绑定执行结果。
- `missed_execution_window`：错过冻结执行日，禁止跨日补成交。
- `blocked_by_contract_validation`：冻结计划合同不合法或不兼容。
- `blocked_by_execution_recovery`：执行中断后为防重复成交而隔离。
- `formal_oos_blocked_by_statistics`：公开 OOS 统计证据不足，等待窗口自然前移。
- `blocked_by_reference`：缺少同任务、同版本、同成本协议的正式对照。
- `awaiting_first_future_signal`：候选账户已建立，等待创建后的首个未来信号。

## 21. 前端控制台

前端是面向项目所有者的只读解释和审计界面：

- 总览：健康、今日计划、账户收益、基准、超额和版本变化。
- 今日决策：市场状态、动作、权重、冻结订单、理由和风险。
- 账户与组合：现金、持仓、净值、调仓、风险贡献和方案竞赛。
- 公司与行业研究：公司证据、行业、主题、事件和研究资产。
- 策略进化：Champion、Challenger、隔离账户、OOS、Shadow 和晋升。
- 模型治理：模型版本、训练、A/B、未来观察和生产资格。
- 因子关系：因子定义、组合、贡献、评价和候选进展。
- 实验与效率：研究波次、专家、任务成本和有效产出。
- 系统：任务、链路、数据日更、版本、证据和审计。

控制台只读取已持久化状态，不能通过刷新页面生成计划、执行交易、晋升候选或修复账本。

## 22. 日常业务流程

盘前和交易时段，系统审计上一计划、成交、账户与账本，推进候选未来观察并监控任务和数据源；盘中数据不会重写冻结计划。

收盘后，发布探针检测数据源，以最快合格来源取得关键数据，生成标准化快照和完整性审计，物化市场状态、因子和必要研究，运行统一选股、Controller 和组合竞赛，冻结 T 日正式计划，并推进日报、归因、候选观察和自治研究。

到下一执行时刻，系统核验交易日历和冻结时钟，补齐订单所需精确 T+1 行情，校验合同、版本、账户、账本、现金和持仓，由唯一执行器完成模拟成交，原子更新账户并绑定计划，随后独立重算账本和账户曲线。

## 23. 当前真实状态

ALIS 已形成数据、正式决策、T+1 模拟执行、独立账本、策略重放、OOS、候选隔离账户、未来观察和自治任务的主体架构，但架构完整不等于策略已经证明有效。

- 系统存在唯一登记 Champion，用于生产对照和日常模拟决策。
- 当前 Champion 的正式 Purged Walk-Forward OOS 失败，说明长期有效性尚未验收；这影响晋升判断，但不是永久交易锁。
- 五个业务模型当前均无生产激活版本，正式选股主要使用生产因子和透明规则。
- 密封历史保留集数据完整，但候选不能绕过公开 OOS 统计门提前消费。
- 候选因子、模型和策略正在通过未来样本或隔离账户积累证据。
- 成本校准仍依赖更多真实模拟买卖样本，充分前继续使用保守成本。

当前重点不是继续堆叠模块，而是让已有闭环在连续真实交易日中稳定积累证据，淘汰无效候选，并找到能在成本、回撤和市场暴露约束下稳定改善 Champion 的版本。

## 25. 项目边界

ALIS 当前明确不包含：

- 券商实盘适配和真实资金交易。
- 融资融券、杠杆和负权重组合。
- 支付、订阅、多租户和 SaaS 能力。
- LLM 自主批准策略或直接生成订单。
- 用人工填值、未来数据或来源不明数据补齐结果。
- 为得到更好结论而覆盖历史证据或反复消费同一密封测试集。

ALIS 的价值不在于保证预测正确，而在于把每次判断放进一个诚实、可复现、能持续学习的系统：知道自己用了什么，知道为什么行动，知道哪里可能错，并在证据不足时明确停下来。
