# AGENTS 工作说明（个人自用量化平台）

> 本文档用于告诉后续接手的 agent：这个项目在做什么、不做什么、下一步该怎么做。  
> 如无用户明确新指令，优先遵循本说明。

## 1. 项目定位（必须先理解）

- 项目名称：量化系统（A 股数据 + 资金模拟 + 回测 + 任务调度）。
- 使用者：项目所有者本人（个人）。
- 核心用途：用于研究量化策略，逐步接入实盘，目标是通过实盘稳定盈利。
- 当前阶段：研究与模拟交易阶段，正在向小资金实盘过渡。

## 2. 战略目标（按优先级）

1. **第一目标：策略有效性**
   - 找到在多市场阶段都具备统计优势的策略，而不是单段历史最优参数。
2. **第二目标：风控与执行可靠性**
   - 让策略在真实执行环境下可控、可停机、可复盘。
3. **第三目标：实盘可放大**
   - 先小仓验证，再逐步加仓，不追求短期暴利。

## 3. 明确不做（除非用户临时改变方向）

- 不做对外 SaaS 产品化。
- 不做对外售卖、订阅收费、支付系统接入。
- 不以“营销包装”为优先任务。
- 不追求功能数量，优先“可盈利性 + 风险控制 + 运行稳定”。

## 4. 业务与工程原则

### 4.1 策略研究原则

- 每次只迭代少量策略（建议 2~3 套主策略 + 1 套基准策略）。
- 严禁仅凭单段回测结果下结论，必须做多区间验证。
- 回测结果必须考虑交易成本、滑点与可交易约束。
- 策略变更要可追踪（改了什么、为何改、预期改善点）。

### 4.2 风控原则

- 先定义风险再追求收益：先定最大回撤容忍度，再定仓位。
- 必须具备停机机制：连续亏损、异常波动、数据异常都能触发降级或停止。
- 新策略必须“模拟 -> 小仓实盘 -> 放量”三阶段推进。
- 任何建议都不得出现“保本/稳赚”等确定性表述。

### 4.3 工程原则

- 优先做“影响交易质量”的改动：
  - 数据质量和一致性
  - 回测可信度
  - 执行稳定性
  - 日志与复盘可读性
- 降低非必要复杂度，避免过度工程化。
- 保持可观测性：任务状态、异常原因、关键指标要可追踪。

## 5. 当前系统能力（供 agent 理解上下文）

- 后端：FastAPI（策略、选股、回测、执行、量化任务、日志等路由已存在）。
- 前端：React 看板（持仓/选股/量化任务/回测/账户/策略/日志模块）。
- 数据与缓存：已有 all-in-one 统一缓存与初始化流程。
- 账户体系：已有登录注册与 token，但系统仍按个人自用思路推进。

## 6. 近期执行路线（建议默认计划）

### 6.1 短期（0~3 个月）

- 目标：证明策略在模拟与历史中稳定可活。
- 重点任务：
  - 固化评估指标（年化、回撤、夏普、胜率、换手、成本后收益）。
  - 统一回测口径，减少“回测-实际”偏差。
  - 优化策略复盘输出（每次执行为什么买、为什么卖、收益来自哪里）。

### 6.2 中期（3~9 个月）

- 目标：小资金实盘验证执行质量。
- 重点任务：
  - 接入实盘前置条件检查（风控阈值、交易时段、资金限制）。
  - 建立灰度机制（策略分级上线，失败自动降级）。
  - 监控实盘偏差（滑点、成交延迟、未成交占比）。

### 6.3 长期（9~24 个月）

- 目标：构建可放大的个人交易引擎。
- 重点任务：
  - 建立策略组合与风险预算框架。
  - 强化市场状态识别（趋势/震荡/高波动）。
  - 形成稳定的季度淘汰与迭代机制。

## 7. 后续 agent 的默认工作顺序

接到任务后，优先按下列顺序执行（除非用户另有要求）：

1. 先确认任务是否直接影响“盈利能力/风险控制/执行稳定”。
2. 再确认是否会引入回测偏差、数据偏差或风控漏洞。
3. 优先最小可行改动（MVP），避免大范围无效重构。
4. 完成后给出可验证结果：
   - 做了什么
   - 为什么做
   - 如何验证
   - 对盈利与风险的预期影响

## 8. 文档与输出要求（给后续 agent）

- 输出以中文简体为主。
- 说明要贴近交易决策，不要只讲技术细节。
- 涉及策略逻辑时，必须给出“收益来源假设 + 失效场景”。
- 涉及实盘建议时，必须同时给出“风控建议 + 退出条件”。

## 9. 任务优先级判断模板（可复用）

如果出现多个任务冲突，按以下优先级取舍：

1. 会导致资金风险扩大或无法止损的问题（最高优先级）
2. 会造成策略评估失真的问题（如数据泄漏、未来函数、不一致口径）
3. 会影响执行稳定性的系统问题（任务中断、状态错乱、异常不可追踪）
4. 用户体验与界面优化
5. 非关键功能扩展

## 10. 关键成功标准（agent 评估任务价值时使用）

- 策略收益是否更可持续（不是一次性优化）？
- 最大回撤是否更可控？
- 回测与模拟/实盘偏差是否缩小？
- 异常是否更早被发现并能自动处理？
- 用户（项目所有者）是否更快做出交易决策？

## 附：一句话原则

**这个项目是“个人交易引擎”，不是“对外产品”。一切工作都应服务于：稳定、可解释、可复现、可控风险的实盘盈利能力。**
