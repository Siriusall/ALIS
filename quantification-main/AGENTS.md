# AGENTS 工作说明：ALIS

> 本文件是 AI/Agent 理解和修改 ALIS 的唯一 Markdown 入口。其他保留的 Markdown 面向项目所有者。  
> 当前口径更新于 2026-07-23（UTC+8）。旧文档、旧对话和旧 README 不再作为实现依据。

## 1. 项目定位

- ALIS 是个人使用的 A 股研究与模拟交易系统，不是 SaaS。
- 当前不接实盘，不建设券商适配、支付、订阅或对外产品能力。
- 第一目标是策略有效性，其次是风险可控、执行可回放和长期稳定运行。
- 最终运行目标是模拟交易范围内全系统无人值守自进化：数据、因子、模型、策略、组合、执行和复盘自动形成闭环；项目所有者默认只查看每日调仓、账户收益和异常。
- 当前代码根目录为 `quantification-main/`：FastAPI 后端、React/Vite 前端、PostgreSQL 双库、Redis、TuShare 与网页备用源。
- `news/` 是历史采集实现，只作迁移来源，不再独立运行。

## 2. AI 默认工作规则

1. 先读取本文件，再读取 `docs/ALIS系统计划书与功能审计.md` 中与任务相关的章节。
2. 2026 年 7 月以前形成的 Markdown 一律视为老版本遗留；若旧结论与当前代码冲突，以当前代码和测试为准。
3. 功能完成不能只看文件、接口或页面是否存在，必须核对主流程、真实数据契约、测试和运行结果。
4. 每次优先完成一个小目标，完成后更新计划书中的勾选状态、日期、文件和验证结果。
5. 不主动扩展实盘接入、外部产品化或运维任务；用户明确要求时再做。
6. 保留用户工作区内未提交改动，不覆盖无关修改。
7. 涉及策略逻辑时说明收益来源假设、失效场景和退出条件。
8. 涉及资金与组合时优先防止数据泄漏、回测失真、重复成交、现金透支和不可交易订单。
9. 默认不把日常因子选择、参数调整、候选审批和版本维护交给项目所有者；应建设确定性硬门下的自动生成、验证、晋升和回退。
10. LLM 只负责研究解释和受约束候选提案；不得直接生成成交、绕过验证、自批候选或覆盖安全合同。关闭 LLM 后核心链路必须继续运行。

## 3. 当前系统架构

```text
TuShare / 交易所 / 网页备用源
  → 原始数据留痕与点时可用性
  → 标准化快照、质量与数据冻结
  → 模型层：识别市场、排序、资金、龙头、事件、叙事和风险
  → StrategyController：决定买入、加仓、减仓、退出、持有和防御切换
  → 组合优化器：决定目标权重
  → 模拟执行层：处理交易单位、费用、滑点、现金和不可交易约束
  → 决策快照、模拟账本与复盘
```

主要运行组件：

- 后端：`backend/app/main.py`，默认 `127.0.0.1:8000`。
- 前端：`frontend/`，默认 `127.0.0.1:5173`。
- 主业务库：PostgreSQL `alis_sim`。
- 数据平台库：PostgreSQL `alis_data`。
- Redis：任务队列、运行日志和缓存协调。
- 生产运行禁止回退 SQLite。

## 4. 当前投资与组合规则

### 4.1 有效框架

- 叙事解释潜在空间，资金确认认可度，价格结构决定时点，基本面与估值决定持有期限。
- 单一叙事、单日资金流或单一模型不得独立触发买入。
- 普通情况下按收盘完整数据生成正式计划，下一交易日执行；页面读取不得触发交易。
- 正常交易日不以长期空仓作为成功结果。股票机会不足时，优先在合格 ETF 和防御资产中配置。
- 模拟账户基准权益为 20 万元；正常交易日资金利用率目标 100%，工程底线 99.5%，尾差现金不超过 500 元。
- 只有市场、数据、账户或最小交易单位等硬故障可以导致零成交，并必须留下复核记录。

### 4.2 已废止规则

以下旧规则不再作为硬约束：

- 进攻/稳健必须各占 45%–55%。
- 五个功能仓必须达到固定中心权重。
- 不同桶固定 8%/10% 单票上限。
- 为满足桶比例而强行买入某类资产。
- 行业没有预分配预算就直接把候选权重清零。

功能仓标签只用于解释和归因。实际权重由预期收益、经验 CVaR、相关性、交易成本、换手、拥挤度和集中度共同决定。

### 4.3 必须保留的安全约束

- 禁止负权重、融资和现金透支。
- 停牌、涨跌停、数据异常资产不得违规新增。
- 股票和 ETF 必须符合最小交易单位。
- 不得超卖现有持仓。
- 单笔订单不得超过流动性容量。
- 收盘数据不完整或过期时不得生成正式执行单。
- 预期改善不能覆盖交易成本时优先保持当前持仓。
- 主优化失败时依次降级到 HRP 或当前持仓，不得为了求解而破坏账户安全。

## 5. 策略总控与模型合同

策略层统一输出：

- `buy_candidate`
- `add_position`
- `reduce_position`
- `sell_exit`
- `hold`
- `defensive_switch`

每个动作必须记录：触发模型、原因、预期收益来源、风险预算、持有周期、退出条件、禁止条件、数据状态和策略版本。

当前模型族：

- `market_regime_hsmm_v1`：市场状态。
- `medium_horizon_lambdarank_v1`：中期排序。
- `capital_persistence_multitask_v1`：资金持续性。
- `leader_lambdarank_v1`：龙头排序。
- `event_surprise_lgbm_v1`：事件预期差。
- `narrative_transition_multitask_v1`：叙事生命周期。
- 组合风险与经验 CVaR 优化器：目标权重和风险预算。

中期排序、资金持续、龙头和事件模型已通过统一信号融合进入选股排序、准入门和 StrategyController 动作合同；关闭任一生产版本会留下明确的降级证据。叙事生命周期模型当前没有通过生产激活门，因此只保留生命周期规则门，不得宣称监督叙事模型已经接管交易动作。

## 6. 因子合同

统一注册表当前登记 24 个因子（16 个生产、8 个候选），主要包括：

- 量价：`volume`、`turnover`、`change_pct`。
- 趋势与波动：`momentum_5`、`momentum_20`、`volatility_20`、`volume_ratio_5`。
- 市值与估值：`float_mv`、`total_mv`、`pe_ttm`、`pb`。
- 交易状态：`is_st`、`is_limit_up`、`is_limit_down`、`is_suspended`。

`beta_60` 已改为读取沪深300逐日点时收益序列；物化、选股、训练、回测、重放和每日决策共用注册版本及点时合同。候选因子仍必须积累至少 20 个未来评价截面后才能晋升，不能因已登记或已物化而宣称有效。

## 7. 数据源与完整性合同

### 7.1 TuShare 调用原则

- 全市场接口优先按交易日、报告期或公告日批量拉取。
- 只有官方要求 `ts_code` 的接口才逐股请求。
- `daily`、`daily_basic`、`adj_factor`、`stk_limit`、`moneyflow` 等按交易日批量。
- 财务 VIP 接口优先按报告期全市场批量，单接口失败后才逐股降级。
- `fina_audit` 等必须逐股的接口采用断点批次。
- 空结果必须区分 `valid_empty`、上游未发布、权限不足和真实失败。
- 所有批量结果必须校验股票、日期、报告期、字段和行数。

### 7.2 数据使用原则

- 原始响应必须留痕并保存来源、参数和可用时间。
- 回测、训练和历史研究只能读取当时已经可用的数据，禁止未来数据泄漏。
- 最新决策硬门至少要求 `daily + daily_basic + stk_limit + 当日快照` 完整。
- 网页/OCR 只能作为低优先级应急来源，必须记录来源、置信度、校验状态并等待结构化来源对账。
- 数据源不存在的数据不能伪造或标记为已补全。

## 8. 当前已确认完成

- PostgreSQL 双库、Redis 和生产禁止 SQLite 回退。
- 数据补全游标、动态重规划、失败记录、续跑和关键 coverage 修复。
- 最新交易日决策数据硬门。
- StrategyController、统一动作合同、策略版本、候选验证和人工审批门。
- 唯一生产 Champion 策略包：`alis_production_strategy` 将选股公式、StrategyController 版本、模型引用、组合优化器和执行合同冻结为一个可追溯版本；每日调仓、策略重放和后续样本外报告默认读取该版本。
- 经验 CVaR 主优化、成本/换手/拥挤度/集中度惩罚和 HRP 降级。
- 正式调仓计划版本、数据截止日、计划执行日和防重复执行。
- 模拟成交账本、费用记录、FIFO 匹配和决策证据冻结。
- 当前持仓回看型组合 K 线与调仓名称、原因、风险贡献展示。
- 前端“策略实验室”：只读展示唯一 Champion、Challenger、正式 OOS、分窗口收益、交易纪律、后台任务、自动晋升与回退状态；页面不直接执行人工晋升。
- 正式诊断基线：`ALIS Baseline 多因子等权 V1`（策略 3、版本 44）五窗口成本后 +1.52%、1/5 跑赢；`ALIS Baseline 简单动量 V1`（策略 4、版本 45）五窗口 -8.55%、0/5 跑赢。统一同期沪深300 +42.76%。结果表明多因子优于单动量、CVaR 略优于等权，主要缺口是上涨市场暴露而非继续微调配权。
- 自进化运行底座 V1：PostgreSQL `evolution_tasks` 持久化任务、租约防重、心跳、自动重试、检查点恢复、安全取消、单 worker、资源预算及每日/每周调度已实现；正式 OOS 可逐窗口持久化并从检查点续跑。
- 策略自治闭环 V1：已实现归因、白名单候选生成、快速诊断、正式 OOS、至少 20 个未来交易日影子观察、确定性自动晋升、冷却监控和自动回退。当前没有 Challenger 通过收益硬门，唯一 Champion 保持不变。
- 统一因子平台 V1：已登记 16 个生产因子和 8 个候选因子，支持版本、依赖、点时物化、IC/Rank IC/分组与成本后增量评价、自动治理和泄漏阻断；真实物化 5,523 只证券、132,552 个因子值。`beta_60`、点时批量统计和 24 因子跨消费实现已修复；20 个未来评价截面仍需自然积累。
- 模型信号融合 V1：中期、资金、龙头和事件四个激活模型以冻结版本进入排序、准入和动作合同；资金底部分位禁止新增，低确认禁止加仓，龙头/事件影响资格与排序。叙事监督模型因无合格激活版本暂不消费。
- 组合方案竞赛 V1：同一截面自动比较经验 CVaR、等权、HRP 与保持当前持仓，只有成本后改善越过硬门才切换；2026-07-23 自治周期选择 HRP。
- 模拟执行成本校准 V1：从模拟成交账本估计买卖侧费用和滑点，只生成未来版本且不改历史。当前仅 16 笔观察，未达到 20 笔候选门和 50 笔自动激活门，继续使用内置保守成本。
- 模拟分红送股 V1：每周分别刷新持仓股票 `dividend` 与上市基金 `fund_div`，按股权登记日模拟持仓冻结资格，现金分红在派息日一次性入账，送股在除权日增加数量；历史账户曲线只读取事件当时可见的数据。无分红记录按 `valid_empty` 留证并进入七日节流，不误报故障或反复请求。
- 模拟账户独立账本 V1：每天从固定本金、逐笔买卖、费用、分红送股和显式迁移调整独立重算现金及持仓数量；现金或持仓漂移立即进入所有者异常并阻断新自动成交。买入的现金、成交、持仓在同一事务提交，卖出投影和成交记录同事务提交；审计不得自动改账。
- 周期复盘学习 V1：日/周/月/年报告按市场状态、模型版本、Champion/Controller 版本、手续费、换手和错误类型冻结；日报使用上一交易日净值，基准缺失日不按零值计算。负超额、高换手、复核错误和阻断信号形成确定性学习信号，只进入 Challenger 治理，不直接改写 Champion 或历史。
- 统一决策版本 V1：数据截止、因子绑定、生产模型、Champion、StrategyController、组合方法/风险预算及执行成本冻结为稳定哈希，并写入正式调仓计划和决策快照。
- 系统自治日任务 V1：已建立硬数据、模型优化、策略候选、成本校准、公司行动、独立账本、收益组合、周期复盘和研究维护的九步骤日循环；2026-07-23 持久自治任务 12 九步骤全部通过。后台唯一 `autonomous_daily` 模拟任务读取 Champion 并自动推进，旧手工回放任务不会被自动调度。
- 所有者首页 V1：首屏展示系统健康、今日调仓、账户日/月收益、点时沪深300同期收益、账户累计超额、账本一致性和系统版本变化，并支持下钻组合方法、成本状态与异常。
- 历史逐交易日策略重放 V1：复用 StrategyController、经验 CVaR、A 股交易约束和费用规则，使用独立内存账本并按 T+1 开盘成交。
- Point-in-Time V1：生产决策和重放统一使用 T 日 15:00 截止；行情、日截面、估值因子和历史窗口执行 `available_time <= cutoff`，财务、公告、事件、新闻、主题、预期、估值和行业研究沿用同一 `as_of_time` 合同；T+1 开盘价只用于成交结果。
- Purged Walk-Forward OOS 引擎：固定 Champion，支持训练/隔离/验证/embargo/测试滚动窗口、成本后组合指标、四市场状态归因和晋升硬门。2026-07-23 已用修正后的 1,537/1,537 硬数据完成 5 个正式窗口；数据、点时、版本和四状态覆盖门通过，但 5/5 窗口均跑输沪深300，组合复合收益约 -99.99%、基准约 +42.76%，正式状态 `failed`。当前 Champion 继续作为唯一登记版本仅用于对照，不得宣称通过有效性验收。
- Champion OOS 永久硬数据合同：固定要求最近 1,537 个交易日的 `daily + daily_basic + stk_limit + adj_factor + 标准化截面 + available_time`；已进入数据资产、Readiness、每日长线自检和统一 Backfill。2026-07-23 修复了旧合同将“单日仅 5 条探针记录”误判完整的问题，`adj_factor` 现在要求单日至少 500 条且点时时间合格；修正后已补至 1,537/1,537、状态 `ready`。补数脚本为 `backend/scripts/backfill_oos_hard_data.py`，默认只审计，显式 `--execute` 才写库。
- UTC+8 业务时间统一。

## 9. 当前未完成重点

详细状态只维护在 `docs/ALIS系统计划书与功能审计.md`。默认顺序：

1. 自然积累至少 20 个未来因子评价截面，完成首批候选因子的真实晋升或淘汰。
2. 继续积累模拟成交观察；达到 20/50 笔硬门后验收成本候选生成与自动激活，随后再校准换手和调仓频率。
3. 为叙事生命周期模型补足点时样本并通过生产门；通过前继续使用确定性生命周期规则。
4. 用未来交易日连续验收 `autonomous_daily` 任务的 T 日计划、T+1 模拟执行、收益归因和异常恢复。
5. 随模拟成交和真实分红事件积累更长账户历史，持续验收独立账本。
6. 最后接入受约束 LLM 研究代理；LLM 不得拥有执行、晋升和回退权限。
