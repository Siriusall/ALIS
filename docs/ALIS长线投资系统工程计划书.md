# ALIS 长线投资系统工程计划书

> 版本：V1.0
> 定位：面向 A 股长线投资的个人研究、决策、组合管理与复盘平台
> 核心边界：系统提高数据可信度、研究一致性、风险识别和复盘质量，不承诺投资收益，不允许任何单一模型或大模型直接决定交易。

---

## 1. 项目愿景

ALIS 不是“因子打分后自动买入”的短线选股器，而是一套围绕事实、研究、投资逻辑、估值、组合和复盘形成闭环的长线投资操作系统。

完整业务链路：

```text
外部数据
→ 原始数据留痕
→ 标准化与时间一致性
→ 数据质量检查
→ 风险过滤
→ 企业/行业/事件/情绪/叙事研究
→ 预期变化判断
→ 多维研究状态
→ 投资逻辑卡片
→ 估值与安全边际
→ 候选池与建仓时机
→ 组合约束和持仓状态机
→ 持续验证
→ 决策快照与复盘学习
```

系统遵循五条原则：

1. 数据先成为事实，不能直接产生买入信号。
2. 固定规则负责底线，统计模型负责概率，市场状态负责环境，LLM 负责文本理解。
3. 企业质量、预期变化、估值、情绪和主题叙事分别建模，不压缩成不可解释的唯一总分。
4. 基本面决定是否值得研究，估值决定是否值得买，技术面与情绪决定买入节奏，组合系统决定买多少。
5. 所有关键判断必须有证据、版本、置信度、失效条件和可回放的决策快照。

## 1.1 已确认的产品与投资边界

### 使用方式

- V1定位为全自动模拟盘研究与策略验证系统，不连接券商真实账户。
- 投资逻辑由系统自动生成、自动验证、自动修正和自动终止；用户不负责逐只股票确认逻辑，只负责目标、风险、禁止项和研究方向引导。
- 模拟盘自动执行调仓、成交模拟、持仓记账、策略调优和版本晋升，不等待用户审批；用户通过前端观察全过程和结果，发现问题后可以暂停、回退、否决或修改约束。
- 真实资金、券商接入和真实自动下单不属于V1。未来进入真实资金阶段前必须新增独立安全评审、人工确认和交易权限控制，模拟盘自动化授权不得自动继承。
- 每个交易日收盘后完成数据更新、市场分析和组合复核，生成下一交易日模拟调仓计划，并按固定成交模型自动执行和记账。
- 每条买入、加仓、减仓、卖出或继续持有建议必须说明事实变化、模型变化、投资逻辑影响、风险影响和预计交易成本。
- 当日没有调仓时也必须说明“为什么继续持有”，不能只输出无信号。
- 盘中分析和盘中调仓属于系统稳定后的二阶段能力，V1不建设，避免回测口径和执行价格不一致。

### 绩效考核

- 每周考核当周收益、回撤、调仓贡献和错误归因。
- 每月考核月度收益、最大回撤、波动、换手、成本、选股与仓位贡献。
- 每年考核年度收益、最大回撤、各市场状态表现和模型稳定性。
- 年化收益目标数值、正式业绩基准和超额收益目标在系统稳定运行后确定；V1先完整记录，不用事后选择的目标反向调整模型。
- 单日盈亏不作为模型成败判断，系统必须持续展示分析是否更新、证据是否有效以及是否符合当前市场环境。

### 风险与仓位

- V1模拟盘初始资金固定为人民币200,000元；所有收益、回撤、费用、仓位和容量报告以该初始净值为基准。
- 组合风险目标：滚动最大回撤控制在10%以内；这是优化和预警目标，不承诺任何市场环境下绝不超过。
- 普通股票单股上限15%，高置信核心股票上限25%；高置信核心仓必须同时满足逻辑置信度、数据质量、安全边际和组合风险约束。
- 正常情况下至少持有5只股票或ETF；资金不足以合理分散时允许减少数量，但必须展示集中度风险。
- 不允许无说明地长期空仓。连续空仓达到3个交易日后，系统必须每日解释继续空仓的原因、恢复建仓条件和替代防御资产评估结果。
- 允许并支持货币ETF、债券ETF、黄金ETF、低波动ETF和红利ETF作为防御资产；风险收缩期优先在防御资产与权益资产之间配置，而不是被迫持有高风险股票。

### 标的与数据范围

- 投资范围固定为沪深A股和沪深市场可交易ETF，不包含港股、港股通和北交所。
- 排除ST、*ST和明确退市风险股票。
- 不因小市值、上市不足一年或低流动性自动排除，但必须施加流动性、可交易性和仓位约束。
- 前端和日常业务默认展示最近两年；模型训练需要 6～10 年历史时，必须在训练任务触发时按需调用 API 获取紧凑训练数据，不做全市场 6～10 年历史的一次性本地落库；仅允许持久化模型必要的指数、宽度、波动、流动性等紧凑特征、训练样本和模型版本证据，具体按附录B的数据要求执行。
- 免费数据源优先；缺少关键数据时系统生成数据采购需求单，说明字段、用途、替代方案、价格价值和缺失影响，由用户决定是否购买。

## 2. 建设优先级定义

| 等级 | 定义 | 处理原则 |
|---|---|---|
| P0 | 系统可信和可运行的基础设施 | 不完成则禁止进入正式研究与决策 |
| P1 | 长线研究最小闭环 | 完成后可以形成可信的研究候选和风险提示 |
| P2 | 动态环境、预期和主题发现能力 | 完成后系统开始具备市场适应性和主线识别能力 |
| P3 | 投资逻辑、估值和组合闭环 | 完成后可以管理完整持仓生命周期 |
| P4 | 模型学习、自动治理和平台化 | 在积累足够历史数据后建设，不提前堆复杂基础设施 |

# P0：可信数据与运行底座

## P0-1 数据源体系

### 目标

建立结构化 API、正式披露、官方网页、网页备用源、OCR 和人工复核的分级数据源体系。

### 数据源优先级

```text
正式结构化 API
→ 交易所/巨潮正式披露
→ 政府与行业官方数据
→ 官方网页
→ 财经网页备用源
→ OCR
→ 人工确认
```

### 必须覆盖

- 股票基础、上市状态、名称/ST 历史
- 交易日历
- 日线、估值、涨跌停、复权、停复牌、资金流
- 三大财务报表、财务指标、审计意见、主营构成
- 股东人数、十大股东、流通股东、质押、分红、业绩预告/快报
- 指数、指数权重
- GDP、CPI、PMI、Shibor、汇率
- 巨潮和交易所公告
- 行业经营指标的导入与采集接口

### 验收标准

- 每个数据资产有主源、备用源、更新频率、字段定义和责任状态。
- 空结果与接口失败分开记录。
- 所有失败请求可分类、重试和续跑。
- 数据源切换不改变下游内部字段契约。

## P0-2 数据仓库分层

```text
Raw：原始 API JSON、HTML、PDF、网页快照、OCR 原件
Clean：统一代码、日期、报告期、单位和字段语义
Feature：财务、估值、行业、事件、情绪和风险特征
Research：企业、行业、预期、主题和风险状态
Decision：投资逻辑、估值、仓位、决策和复盘
```

每条关键数据必须保存：

```text
source
source_record_id
report_period
announcement_time
available_time
ingestion_time
revision_version
quality_status
content_hash
```

### 时间一致性

回测和历史决策只能使用：

```text
available_time <= decision_time
```

修订后的财报不得覆盖历史决策当时可见的版本。

## P0-3 增量更新与全量补全

### 更新频率

| 频率 | 数据 |
|---|---|
| 每日 | 行情、估值、涨跌停、停复牌、资金流、复权、指数、利率、汇率、公告 |
| 每周 | 股票名单、名称/ST 历史、质押、分红与治理事件检查 |
| 每月 | 指数权重、CPI、PMI、行业经营数据 |
| 每季度 | 财务报表、财务指标、股东、业绩快报、GDP、行业模板重算 |

### 任务要求

- 用户层面一次启动，全量补完。
- 系统内部以小批次持久化断点。
- 默认受控并发，不允许无限并发请求上游。
- 成功数据、成功空结果和失败请求分别留痕。
- 重启后从数据库缺口继续，不依赖内存进度。
- 单接口失败不能让全部任务丢失进度。
- 磁盘低于安全阈值时自动暂停，不允许写满数据库。

## P0-4 数据质量与可观测性

质量检查包括：

- 唯一键和重复记录
- 股票代码、交易日和报告期合法性
- 开高低收关系
- 复权前后异常
- 财务恒等关系
- 单位和数量级异常
- 跨源差异
- 数据新鲜度
- 数据覆盖率
- 未来日期和未来函数
- 修订数据版本

运行可观测性包括：

- 当前任务、步骤、股票、日期、接口
- 单条实时日志
- 每分钟处理速度
- 预计剩余时间
- 重试次数和错误分类
- 失败队列
- 断点位置
- 数据库、Redis、磁盘和上游健康状态

## P0-5 存储演进

数据库路线固定：当前本地补数任务可以继续读取现有 SQLite，但不得再为 SQLite 新增业务表或专有逻辑；所有新表、研究引擎和组合功能直接按 PostgreSQL 设计。P0 完成前执行一次 SQLite → PostgreSQL 迁移，此后本地、测试和云端统一使用 PostgreSQL。

目标存储：

```text
PostgreSQL：在线事实、状态、研究、组合和决策数据
Redis：任务状态、缓存、限流、短租约锁和 Redis Streams 任务队列
MinIO（本地）/兼容 S3 对象存储（云端）：公告 PDF、年报、网页快照、研报和 OCR 原件
Parquet：历史行情、原始接口和因子归档
```

最迟迁移条件（任一发生前必须完成；不再作为是否迁移的讨论项）：

- 上云部署
- 两个以上后端实例
- 多台机器共享数据库
- 数据库超过 20～30GB
- 持续锁等待或查询 P95 超过 1 秒
- 需要在线备份、时间点恢复和容灾

# P1：长线研究最小闭环

## P1-1 风险过滤引擎

### 硬否决

- ST、*ST、退市风险和无法交易
- 重大财务造假、债务违约和严重治理问题
- 重大立案调查
- 严重非标审计意见
- 数据严重缺失或可信度不足
- 流动性不足

输出：

```json
{"eligible": false, "reason": "重大治理风险"}
```

### 强预警

- 高比例质押
- 连续减持
- 商誉占比异常
- 应收和存货异常
- 利润和现金流长期背离
- 频繁跨界并购
- 大额关联交易
- 高客户集中度

输出风险等级、最大仓位和人工复核要求，不只扣分。

## P1-2 企业分类引擎

每家公司必须具备：

1. 行业标签：银行、消费、医药、半导体、制造、资源、公用事业等。
2. 商业模式标签：品牌、规模制造、平台、订阅、项目制、资源周期、金融杠杆等。
3. 生命周期标签：高速成长、稳定成长、成熟现金牛、周期底部、周期顶部、困境反转、衰退。

系统根据标签匹配行业研究模板，禁止使用同一组固定阈值评价所有企业。

## P1-3 企业基本面引擎

计算并保留：

- 收入、利润、扣非利润增长
- 三年 CAGR
- 毛利率、净利率、ROE、ROIC
- 经营现金流、自由现金流
- 资产负债率、有息负债、现金覆盖
- 应收、存货、商誉
- 分红、回购和资本配置
- 盈利稳定性和周期性

输出多维状态：

```text
quality_score
growth_score
cashflow_score
solvency_score
governance_score
risk_score
```

## P1-4 行业景气引擎基础版

行业指标模型：

```text
industry_metric_definition
industry_metric_value
industry_metric_mapping
```

核心变量：

- 价格、销量、订单、库存
- 产能利用率、出口、资本开支
- 龙头份额、盈利预测、政策
- 行业估值、成交额和相对强度

行业状态：

```text
衰退 → 筑底 → 复苏 → 扩张 → 过热 → 回落
```

## P1-5 公告事件引擎基础版

V1 固定支持且必须全部完成：

- 财报、业绩预告、业绩快报
- 分红、回购、增减持、质押
- 监管函、问询函、立案
- 重大合同、并购重组、定增

标准输出：

```text
event_type
direction
severity
confidence
impact_horizon
impact_dimensions
evidence
followup_date
```

LLM 固定只做分类、字段抽取、摘要和证据定位；结构化结果必须经过 JSON Schema、数值范围、实体关系、原文引用四类校验。未通过校验的结果进入人工复核，不写正式事件表。

## P1-6 多维研究状态

禁止使用单一总分直接决定买入。至少保留：

```text
quality_score
growth_score
cashflow_score
industry_score
expectation_score
valuation_score
governance_score
risk_score
```

输出研究分类：

```text
高质量低估
高质量合理估值
高质量但过贵
景气反转
预期上调
高股息稳定
困境反转
低估但质量一般
风险恶化
```

# P2：动态市场、情绪、叙事和预期

## P2-1 市场状态引擎

市场状态不直接选股票，输出环境概率：

```json
{
  "risk_on": 0.18,
  "risk_off": 0.56,
  "liquidity_tight": 0.69,
  "earnings_recession": 0.42,
  "high_volatility": 0.64
}
```

特征包括：

- 宽基趋势和市场宽度
- 波动率、回撤和尾部风险
- 成交额、换手、Shibor 和信用环境
- 盈利上调/下调比例
- 全市场估值和股债收益差
- 大小盘、成长价值和高低波动风格

生产路线固定为附录 B 的四状态 HSMM + BOCPD。历史数据不足六年时，规则状态机是唯一生产门控，HSMM影子运行；满足训练和上线硬指标后，HSMM自动进入既定生产角色，不再重新选模型。

## P2-2 市场情绪引擎

情绪状态：

```text
冰点 → 修复 → 升温 → 活跃 → 亢奋 → 高位分歧 → 退潮 → 恐慌
```

维度：

- 市场宽度
- 赚钱效应
- 风险偏好
- 流动性
- 拥挤度
- 背离程度

情绪影响买入节奏、安全边际和仓位，不改变企业质量事实。

## P2-3 主题叙事引擎

主题发现路径：

1. 政策、公告、研报和新闻的文本主题聚类。
2. 股票价格和成交额的异常共振聚类。
3. 龙头到产业链的资金扩散。
4. 订单、价格、库存、出口和业绩的基本面异动。

建立主题知识图谱：

```text
主题 → 产业链环节 → 行业 → 公司 → 产品 → 收入/利润暴露 → 证据
```

主题生命周期：

```text
萌芽 → 启动 → 扩散 → 加速 → 亢奋 → 分化 → 退潮 → 沉寂
```

主题评分维度：

- 叙事强度 15%
- 价格确认 15%
- 板块宽度 15%
- 资金持续性 15%
- 基本面可验证性 20%
- 催化剂持续性 10%
- 政策/信息源可信度 10%
- 拥挤与透支风险最高扣 20 分

主题内公司评分：

- 业务暴露真实性 25%
- 收入利润贡献可能性 20%
- 产业链地位 15%
- 公司竞争力 10%
- 基本面质量 10%
- 市场领导力 10%
- 估值和拥挤风险 10%

## P2-4 预期变化引擎

计算：

- 同比、环比和最近四季度趋势
- 增长加速度
- 毛利率和现金流变化
- 实际结果相对一致预期或内部预测的偏差
- 收入、利润、EPS、自由现金流预测版本变化
- 行业景气拐点

输出：

```text
expectation_state
earnings_revision
growth_acceleration
margin_trend
industry_confirmation
surprise_probability
```

## P2-5 动态策略门控

动态调整的是：

- 安全边际要求
- 仓位上限
- 模型权重
- 建仓节奏
- 不确定性惩罚

不动态改变：

- 数据真实性
- 审计和治理风险事实
- 债务违约事实
- 未来函数规则
- 单股和行业风险底线

# P3：投资逻辑、估值和组合闭环

## P3-1 投资逻辑卡片

每只核心候选必须保存：

```text
thesis_type
core_hypotheses
verification_metrics
expected_ranges
catalysts
failure_conditions
target_horizon
next_review_date
evidence
```

每次更新自动判断：

```text
逻辑加强
逻辑不变
逻辑轻微削弱
逻辑严重破坏
逻辑证伪
```

投资逻辑卡片是策略引擎的可解释状态，不是用户手工研究笔记。系统必须自动完成：

```text
候选机会发现
→ 自动生成一条或多条可证伪投资假设
→ 绑定财务、行业、事件、情绪、主题和估值证据
→ 估计逻辑成立概率、收益区间和失效风险
→ 每日复核新证据
→ 自动加强、削弱、替换或证伪逻辑
→ 将变化传递给调仓与组合引擎
```

用户不逐条审批投资逻辑，也不审批模拟盘的普通调仓和策略晋升。用户的职责固定为：设定收益与风险目标、禁止标的、允许资产范围、关注主题和研究问题；查看系统依据、过程与结果；发现问题后暂停策略、回退版本、否决方向或修改约束。用户干预必须留痕，不能直接改写历史模型输出。

每张卡片必须显示：

- 当前主逻辑、备选逻辑和各自成立概率。
- 逻辑由哪个策略/模型版本生成。
- 支持证据、反对证据、数据来源和更新时间。
- 相比昨日新增、失效或权重变化的证据。
- 预期收益区间、持有窗口、安全边际和主要风险。
- 触发加仓、减仓、退出和重新评估的条件。
- 系统过去如何修改该逻辑，以及修改后是否改善预测。
- 系统自动调优和晋升记录，以及用户后续干预、否决和参数调整记录。

## P3-2 估值与安全边际

| 企业类型 | 方法 |
|---|---|
| 稳定盈利 | PE、DCF |
| 银行保险 | PB、ROE |

## P3-7 每日调仓解释与周期考核报告

V1在每个交易日收盘、数据质量检查通过后生成报告：

```text
一、今日市场环境及相对昨日的变化
二、组合收益、回撤、风险预算和防御资产状态
三、逐笔模拟调仓：标的、方向、目标仓位、计划价格、模拟成交价格
四、调仓理由：新事实、评分变化、逻辑变化、估值、风险和交易成本
五、未调仓持仓：继续持有的理由和下一触发条件
六、被拒绝信号：因数据、风险、流动性或置信度未执行的机会
七、明日需要观察的数据、公告、价格和失效条件
八、策略引擎今日进行了哪些学习、校准或Challenger试验
```

执行口径固定为收盘后生成、下一交易日模拟执行。V1默认使用下一交易日开盘价加滑点和费用；涨跌停、停牌、成交量不足时不得假设成交，未成交订单进入明确状态。计划不得使用生成报告时不可获得的下一日数据。盘中版本建设前，回测和模拟盘统一采用同一成交规则。

每周、每月和每年报告都必须包含：绝对收益、阶段最大回撤、换手、交易成本、现金/防御资产贡献、个股选择贡献、行业配置贡献、市场状态门控贡献、模型失误和人工未执行差异。年化收益目标和正式比较基准暂不写死，待系统稳定后通过组合政策ADR确定。

前端必须单独提供“策略工作台”：展示系统当前在分析什么、为何建立或修改某条投资逻辑、Champion和Challenger的版本差异、回测/影子结果、参数变化、特征贡献、失败实验、漂移告警和待用户参与的调优决议。失败实验不得隐藏，避免只展示事后最优结果。

前端必须单独提供“模拟执行账本”：逐笔展示信号时间、当时可用数据、目标仓位、订单、成交假设、滑点、费用、未成交原因、持仓变化、盈亏和对应策略版本。过程数据不可事后覆盖，策略回退也必须保留原始模拟结果。

### P3-7A 模拟成交和费用模型

V1固定采用保守成交假设，避免产生无法实现的回测收益：

- 信号在T日收盘后生成，订单在T+1日尝试成交。
- 有开盘价且可正常交易时，以T+1开盘价加减滑点模拟成交；停牌、开盘即封死涨跌停或成交量不足时不成交。
- A股默认滑点单边10bp，ETF默认5bp；20日平均成交额参与率超过0.5%后追加平方根冲击成本。
- 券商佣金在用户未提供真实费率前固定按成交额0.03%双边计提，每笔最低5元；用户提供真实费率后只更新费用配置，不重写历史账本。
- A股卖出印花税按当前有效规则0.05%计提；ETF不计股票交易印花税。交易所经手费、监管费和过户费按成交日对应的版本化官方费率表计算，不把费率永久硬编码在模型中。
- 买入数量遵守交易所最小申报单位和可用资金；V1按20万元模拟本金执行。未来切换到小资金参数时，如无法分散到5只标的，系统必须展示资金和最低佣金造成的不可行原因。
- 订单、部分成交、拒绝、过期和取消分别记账；未成交不得按目标仓位计算收益。
- 费用规则带 `fee_schedule_version` 和生效日期，历史模拟使用当时费率，不得用新费率覆盖。

当前交易收费依据包括[上交所收费标准](https://www.sse.com.cn/lawandrules/sselawsrules2025/charge/c/c_20250610_10781461.shtml)、[深交所2026年收费标准](https://investor.szse.cn/marketServices/deal/payFees/index.html)及[财政部、税务总局证券交易印花税公告](https://shanghai.chinatax.gov.cn/tax/zcfw/zcfgk/yhs/202308/t468451.html)。券商佣金属于用户账户条件，因此使用独立可配置参数。

# P4：模型治理、学习与平台化

## P4-1 专业模型体系

禁止一个万能模型端到端输出买卖。拆分为：

- 企业质量恶化模型
- 行业景气和拐点模型
- 盈利预期变化模型
- 估值区间模型
- 公告事件影响模型
- 市场状态与情绪模型
- 主题启动、持续和退潮模型
- 组合尾部风险模型

## P4-2 LLM 研究系统

LLM 负责：

- 公告分类和字段抽取
- 年报摘要和管理层表述变化
- 新旧报告差异
- 主题发现和产业链映射草稿
- 投资逻辑矛盾检测
- 风险点和待核查问题

LLM 不负责：

- 计算确定性财务指标
- 直接预测价格
- 直接决定买卖和仓位
- 修改硬风险规则
- 取代数据质量、回测和人工复核

## P4-3 模型治理

每个模型保存：

```text
model_id
model_version
training_window
feature_version
data_version
validation_result
calibration_result
deployment_time
retired_time
```

采用 Champion/Challenger：

- Champion：线上正式模型
- Challenger：影子预测
- 新模型只有在滚动样本外验证中稳定胜出才替换

## P4-3A 策略自学习与调优闭环

系统可以自动学习和调优，但不得在线无审查地改写正式策略。固定流程：

```text
生产策略产生预测与调仓建议
→ 保存预测、逻辑、仓位和实际结果
→ 周/月/年进行误差与收益归因
→ 自动生成新的参数、权重或特征候选
→ Challenger滚动样本外回测和影子运行
→ 与Champion比较收益、回撤、成本、稳定性和解释质量
→ 前端展示差异及调优理由
→ 达到硬指标后由系统自动灰度晋升
→ 持续监控，异常时自动回退并通知用户
→ 用户可在任何阶段人工暂停、否决或回退
```

自动调优允许改变：模型参数、允许范围内的引擎权重、阈值、状态转移概率、特征选择、评分到收益的校准曲线和风险预算乘数。

自动调优禁止改变：数据时间一致性、ST排除、最大回撤目标、资产范围、硬风险规则、用户设置的仓位上限、模拟盘/真实盘边界和附录B确定的模型职责。这些属于系统宪法，只有用户明确修改规划书或策略治理决议后才能改变。

策略版本晋升必须同时满足：

- Purged walk-forward样本外验证通过。
- 扣除交易成本后优于或不劣于当前Champion。
- 最大回撤目标、尾部风险和约束满足率不恶化。
- 至少跨越多个市场状态，不能依赖单一月份、行业或主题。
- 影子运行达到规定观察期，实盘方向与回测校准没有明显漂移。
- 前端已经生成可读的改动说明和影响范围。
- 晋升先分配10%模拟风险预算运行5个交易日；无硬错误后提高至50%，再运行10个交易日后才可成为100% Champion。

用户人工介入方式：

- 调整收益、回撤、换手和集中度目标。
- 对系统提出研究方向，例如更关注小市值、主题持续性或现金流。
- 查看Champion/Challenger对比；正常情况下无需批准，发现问题时可以否决晋升或回退。
- 标记某次建议“逻辑不认可、数据错误、执行原因未跟随”等反馈。
- 查看反馈是否被吸收到后续候选模型，禁止直接用单次主观反馈覆盖模型。

## P4-4 漂移与降级

```text
模型正常：规则 + 模型
轻度漂移：降低模型权重
严重漂移：停用模型，仅保留规则和人工研究
数据异常：禁止生成新决策
模型冲突：进入人工复核
```

## P4-5 验证体系

使用滚动样本外测试，不允许随机打乱金融时间序列。

评价：

- 收益、最大回撤、波动、盈亏比
- 换手率、交易成本和尾部损失
- 模型校准和置信度
- 行业和风格集中度
- 牛市、熊市、高波动、低流动性和风格切换环境稳定性

# 附录 A：核心评分、权重与研究闭环工程规范

本附录是 ALIS 的核心决策规范。这里给出的百分比固定为V1工程先验，不宣称已被证明长期有效。开发时不得调整；上线后也只能按A6、B14和C11的时间切分、滚动样本外验证、状态检验和ADR程序，在规定边界内校准。

## A1. 总体原则：不使用一个万能总分

系统按四层顺序执行，上一层未通过时，下一层不得用高分抵消：

```text
数据质量与硬风险门控
        ↓
企业、行业、事件、预期等研究向量
        ↓
投资逻辑与入场条件
        ↓
组合风险预算与目标仓位
```

同一家公司必须同时保留独立维度：`quality`、`growth`、`cashflow`、`governance`、`industry`、`expectation`、`valuation`、`sentiment`、`narrative`、`technical`、`risk`、`thesis_confidence`。总分只用于列表排序，不直接产生买入动作。

三种任务使用三套权重，不得混用：

| 决策任务 | 回答的问题 | 主要依据 |
|---|---|---|
| 研究准入 | 值不值得深入研究 | 企业质量、治理、现金流、行业、长期成长 |
| 入场判断 | 现在是否适合买 | 估值、预期变化、市场状态、情绪、叙事、技术确认 |
| 仓位决定 | 买多少、组合风险多大 | 逻辑置信度、安全边际、边际风险、流动性、相关性 |

## A2. 单指标标准化与证据置信度

### A2.1 标准化

每个原始指标先去极值，再分别计算行业横截面分位和自身历史分位：

```text
cross_score = 同行业、同商业模式、同生命周期公司的稳健分位
time_score  = 公司自身 3～5 年历史稳健分位
metric_score = 0.65 × cross_score + 0.35 × time_score
```

默认使用中位数/MAD 或 2.5%～97.5% 分位去极值。周期行业在利润高点不得直接因利润增速获得高分，必须用正常化利润、库存和价格周期修正。银行、保险、地产等行业必须走独立模板。

指标方向统一映射到 0～100；区间最优指标使用钟形或分段函数，不能简单认为越大越好。所有计算保存原值、分位、同行样本、版本和当时可用时间。

### A2.2 置信度

评分和证据置信度必须分开：

```text
C = source_quality
  × data_completeness
  × freshness
  × model_calibration
  × evidence_consistency
```

每项取 0～1。多来源互相印证可提高一致性；缺失值不得自动记为中性。展示值为 `score / confidence / coverage`，并给出合理区间。

V1固定门槛：

- `C < 0.40`：不得新建仓，只能进入待补数据队列。
- `0.40 ≤ C < 0.60`：只能观察或人工研究。
- `0.60 ≤ C < 0.75`：允许进入候选池，但仓位折扣。
- `C ≥ 0.75`：允许按正常规则评估。

## A5. 风险门控和组合优化

风险输出：

| 风险级别 | risk_budget_multiplier | 默认动作 |
|---|---:|---|
| 正常 | 1.00 | 正常评估 |
| 关注 | 0.75 | 降低目标仓位 |
| 高风险 | 0.50 | 仅小仓位或人工复核 |
| 极高风险 | 0.25 | 原则上不新开仓 |
| 否决 | 0.00 | 排除或退出 |

组合目标函数采用“预期收益效用 - 风险 - 交易成本”，而不是最大化评分：

```text
max  calibrated_expected_return
   - λ × portfolio_risk
   - κ × turnover_and_cost
```

约束固定包括：总仓位、单股上限、行业上限、主题上限、因子暴露、相对基准偏离、流动性、换手和最大回撤预算。正式组合固定使用附录B的Black-Litterman观点融合与约束CVaR优化；HRP是唯一风险降级基线，不再在实现阶段选择其他优化器。

当优化失败时必须显式降级：先放松换手约束，再使用当前权重或风险预算基线，不得静默输出异常仓位。

## A6. 动态权重：只允许有边界的学习

市场会变，但不能让模型随短期行情任意改写权重。动态权重由“工程先验 + 样本外证据 + 市场状态”组成：

```text
w* = argmin(
    out_of_sample_loss
  + λ × ||w - w_prior||²
  + γ × weight_turnover
)
```

约束：`w ≥ 0`、总和为 1、每个引擎在 A4 的范围内、单次季度调整不超过 3 个百分点。引擎可靠度由以下组成：

| 可靠度项 | V1占比 |
|---|---:|
| 样本外 IC/IR 或预测能力 | 30% |
| 不同市场状态稳定性 | 25% |
| 时间稳定性 | 20% |
| 数据覆盖与可用性 | 15% |
| 校准度与可解释性 | 10% |

市场状态只能在允许范围内调整权重和阈值。例如风险状态可提高质量、现金流、安全边际权重，降低叙事和高弹性成长权重；复苏状态可适度提高预期变化和行业景气权重。硬风险、会计事实和历史披露不得动态改变。

## A7. 研究闭环与归因

每次评分都冻结：

```text
decision_time
available_data_snapshot
engine_version
feature_version
weight_version
market_regime
score_vector
confidence_vector
expected_horizon
expected_direction_and_range
```

验证周期：

- 日度：数据异常、事件、风险门控和持仓状态。
- 周度：市场状态、情绪、主题生命周期和组合暴露。
- 月度：因子 IC、排序稳定性、校准误差、换手和交易成本。
- 季度：财务与投资假设复核、权重 Champion/Challenger 评审。
- 年度：行业模板、标签体系、长期归因和模型淘汰。

归因必须拆分为：标的选择、行业配置、市场状态门控、入场时机、仓位管理、交易成本和数据/模型错误。不能只用最终盈亏反推某个引擎“正确”。

## A8. 回测与上线准入

所有权重修改必须通过：

1. 按时间滚动的训练、验证、测试，严禁随机切分代替时序验证。
2. 使用当时可获得的数据，处理幸存者偏差、复权、停牌和退市。
3. 同时报告 IC/IR、命中率、校准误差、收益、波动、最大回撤、换手、成本和容量。
4. 跨牛市、熊市、震荡、流动性冲击和行业轮动状态验证。
5. 使用多重检验、Deflated Sharpe Ratio 和回测过拟合概率审查候选模型。
6. Challenger 连续多个窗口优于 Champion，且没有显著恶化尾部风险，才允许灰度替换。
7. 模型失效、数据缺失或漂移时自动回退到透明规则和较低风险预算。

LLM 的文本判断必须单独测量字段准确率、证据引用正确率、前后一致性和幻觉率；LLM 不直接生成最终仓位。

## A9. 研究依据与工程借鉴

- [Microsoft Qlib](https://github.com/microsoft/qlib)：借鉴研究工作流、增强指数、风险模型、换手和暴露约束；其示例也说明简单 Top-K 难以完成风险控制。
- [Riskfolio-Lib](https://github.com/dcajasn/Riskfolio-Lib) 与 [skfolio](https://github.com/skfolio/skfolio)：借鉴风险预算、HRP/HERC、CVaR、回撤风险、Black-Litterman、状态调整协方差和组合约束。
- [vectorbt](https://github.com/polakowo/vectorbt) 与 [bt](https://github.com/pmorissette/bt)：用于滚动回测、策略组合和工程验证，不作为收益有效性的证据。
- [Gu、Kelly、Xiu：Empirical Asset Pricing via Machine Learning](https://www.nber.org/papers/w25398)：支持用严格样本外框架比较非线性模型，但不意味着端到端黑盒应取代约束和解释。
- [Asness、Frazzini、Pedersen：Quality Minus Junk](https://doi.org/10.1007/s11142-018-9470-2)：为盈利、成长、安全和分红等质量维度提供研究参考。
- [Baker、Wurgler：Investor Sentiment and the Cross-Section of Stock Returns](https://www.nber.org/papers/w10449)：支持把情绪作为横截面收益与风险状态的一部分，而不是企业价值事实。
- [Shiller：Narrative Economics](https://www.nber.org/papers/w20661)：为叙事传播和经济行为的关系提供理论参考；ALIS 仍要求用价格、资金和基本面证据验证主题。
- [Black、Litterman：Global Portfolio Optimization](https://doi.org/10.2139/ssrn.1314585)：用于将先验与带置信度的观点结合，减少直接使用噪声预测的极端仓位。
- [Bailey、López de Prado：The Deflated Sharpe Ratio](https://doi.org/10.2139/ssrn.2460551) 与 [The Probability of Backtest Overfitting](https://doi.org/10.21314/JCF.2016.322)：用于多重尝试和回测过拟合治理。

上述研究只用于设计方法与验证纪律，不构成对A股收益的保证。A3/A4权重作为V1生产先验直接实施，不在开发阶段重新选择；积累足够的ALIS点时数据后，只能按A6和C11执行受限校准。

# 附录 B：ALIS 固定计算模型栈（Model Constitution V1）

## B1. 什么应当钉死，什么不能钉死

从 V1 起固定以下内容，除非进行架构级版本升级，否则不得临时更换：

- 每个业务问题对应的模型家族。
- 模型的输入字段、输出契约、训练窗口和更新频率。
- 数据切分、验证方法、风险门控、降级路线和审计字段。
- 生产模型与 Challenger 的晋升规则。

不能钉死以下内容：模型参数、状态转移概率、特征分布、预测校准曲线、协方差、行业模板参数。它们必须按计划重新估计。固定参数等于假设市场永远不变，违背引入动态模型的目的。

## B2. 最终固定模型总表

| 系统问题 | 生产模型 | 辅助/报警模型 | 明确不采用 |
|---|---|---|---|
| 市场状态识别 | 4 状态 Hidden Semi-Markov Model（HSMM） | Bayesian Online Change Point Detection（BOCPD） | 单一均线、纯人工牛熊标签、端到端强化学习 |
| 宏观与盈利周期 | 动态因子模型 + 状态空间/Kalman Filter | Markov-switching regression | 用单个宏观指标判断周期 |
| 个股横截面预期收益 | LightGBM LambdaRank/回归集成 | Elastic Net 基线 | 直接用神经网络或LLM预测股价 |
| 财务质量和异常 | 行业化规则 + Robust Z-score + Isolation Forest | LightGBM 异常分类 | 单一全行业阈值 |
| 行业景气 | 动态因子模型 + Kalman Filter | HSMM 行业状态层 | 只看行业指数涨幅 |
| 盈利预测 | 分位数 LightGBM | Elastic Net + 分析师一致预期融合 | 只外推历史同比 |
| 公告事件影响 | 规则/LLM抽取 + Gradient Boosting 分类 | Cox 生存/离散时间风险模型 | LLM直接给买卖结论 |
| 主题发现 | 动态主题聚类 + 图传播 | 变点检测、时间衰减 | 只按新闻词频或涨停标签 |
| 主题公司映射 | 知识图谱规则 + 有监督排序 | 文本语义相似度 | 仅按公司简称/概念板块 |
| 波动率 | GJR-GARCH(1,1)-t | EWMA 应急基线 | 普通历史标准差作为唯一估计 |
| 相关性和协方差 | Ledoit-Wolf 非线性收缩 | DCC-GARCH 用于组合级动态乘数 | 原始样本协方差直接求逆 |
| 组合先验与观点融合 | Black-Litterman | 置信度折扣 | 直接把评分当预期收益 |
| 最终组合 | 约束 CVaR 优化 | HRP 风险基线和降级方案 | 无约束均值方差、端到端 RL 配仓 |
| 投资逻辑状态 | 贝叶斯证据更新 + 必要条件状态机 | 规则告警 | LLM自由裁决逻辑是否成立 |
| 模型解释 | SHAP + 单调性/局部敏感度 | 规则证据链 | 只展示一个总分 |

## B3. 市场状态：固定采用 HSMM + BOCPD

### B3.1 为什么不是普通马尔可夫链

普通 HMM 隐含状态持续时间服从几何分布，容易频繁跳转。金融市场的牛市、压力期和流动性收缩通常具有不同且非几何的持续期，因此生产模型固定使用 HSMM，显式估计各状态驻留时间。金融研究表明，状态切换模型可以描述均值、波动、相关性和风险收益关系跨状态变化；半马尔可夫扩展则允许更灵活的驻留时间。

### B3.2 固定四状态

```text
S0 风险扩张：上涨宽度高、波动低、流动性改善
S1 震荡分化：指数稳定但宽度/盈利扩散分化
S2 风险收缩：趋势弱、波动上升、流动性下降
S3 恐慌修复：极端风险后波动高但宽度和流动性边际修复
```

状态含义固定，模型标签不得因训练结果任意互换。训练后根据状态中心特征自动映射，再由规则校验。

### B3.3 固定输入

按周频训练，全部先做滚动稳健标准化：

- 沪深300、中证500、中证1000的 20/60/120 日收益和趋势斜率。
- 全市场上涨比例、站上 20/60/120 日均线比例、创新高/新低比例。
- 实现波动率、下行波动率、偏度、尾部损失、波动率期限结构。
- 成交额、换手率、Amihud 非流动性、涨跌停数量与封板率。
- 行业收益扩散度、行业相关性、横截面离散度。
- 股债收益差、估值分位、盈利预测扩散与修正比例。

不得把个股未来收益或之后才能获得的财务数据放入状态识别。

### B3.4 固定分布与持续期

- 观测分布：多元 Student-t，降低肥尾和异常值影响。
- 状态数：固定 4，不根据样本内 BIC 临时改成 2、3、5 状态。
- 持续期：截断 Negative Binomial；最短 2 周，最长 52 周。
- 训练窗口：最近 10 年或全部高质量历史，取较短者；少于 6 年不得上线。
- 参数更新：每月重估；状态概率每日过滤更新。
- 切换确认：新状态后验概率连续 3 日 ≥0.65，或单日 ≥0.85。

这里与“业务明细只保留两年”不冲突：个股财务、行情和事件业务库按两年范围建设。市场状态模型需要 6～10 年训练窗口时，由训练任务按需调用 API 获取必要历史，不允许把全市场 6～10 年个股明细一次性落入本机业务库。训练任务只能持久化规模可控的指数、宽度、波动、流动性等紧凑特征、训练样本和模型版本证据，进入 `model_training_history`/Parquet 冷数据层；不训练时不得主动补拉长历史。若暂时拿不到六年完整市场宽度，则先用指数、波动和成交特征运行透明状态机，HSMM仅影子运行，不得控制真实仓位。

### B3.5 BOCPD 的职责

BOCPD 每日监控波动、流动性、宽度和相关性，输出 `p_change_1d`、`p_change_5d` 和当前 run length。它只负责报警和加快再评估，不直接指定新状态。

```text
p_change_1d ≥ 0.60 → 市场状态进入待确认
p_change_1d ≥ 0.80 → 临时将新增风险预算乘以 0.70
连续 3 日 < 0.30 → 解除临时保护
```

### B3.6 状态对系统的固定作用

| 状态 | 总风险预算 | 首笔仓位 | 安全边际门槛 | 叙事权重乘数 |
|---|---:|---:|---:|---:|
| S0 风险扩张 | 1.00 | 1.00 | 1.00 | 1.10 |
| S1 震荡分化 | 0.85 | 0.75 | 1.10 | 0.90 |
| S2 风险收缩 | 0.55 | 0.50 | 1.35 | 0.60 |
| S3 恐慌修复 | 0.70 | 0.50 | 1.25 | 0.75 |

乘数是组合门控，不修改公司历史质量分。

## B4. 宏观和行业周期：动态因子模型 + Kalman Filter

宏观序列频率不同、缺失多且存在修订，固定采用状态空间动态因子模型：

```text
x_t = Λ f_t + ε_t
f_t = A f_(t-1) + η_t
```

Kalman Filter/双向平滑分别产生“当时可用 nowcast”和事后研究值。生产决策只用过滤值，回测必须使用当时的数据版本。

固定宏观因子：增长、通胀、信用、流动性、地产、外需；固定行业因子：需求、价格、库存、产能、利润扩散、政策。每个行业先由行业模板选择原始序列，再由模型提取 1～3 个公共因子。

```text
industry_cycle_score =
  0.30 × demand_factor
+ 0.20 × price_factor
+ 0.20 × inventory_inverse_factor
+ 0.15 × profit_diffusion
+ 0.15 × policy_supply_factor
```

更新频率按数据源执行，因子每日重新过滤、月度重估载荷。行业状态仍映射为衰退、筑底、复苏、扩张、过热、回落；连续两期确认后才正式切换。

## B5. 个股横截面模型：LightGBM + Elastic Net

### B5.1 预测目标

不预测明天价格，固定预测三个横截面目标：

- `y_63d`：未来 63 个交易日行业中性超额收益。
- `y_126d`：未来 126 日行业中性超额收益。
- `y_252d`：未来 252 日超额收益，只作为长期排序辅助。

训练标签扣除可实现交易成本；停牌和无法成交样本按实际可交易日处理。

### B5.2 固定模型集成

```text
expected_return_rank =
  0.50 × LightGBM_LambdaRank
+ 0.30 × LightGBM_quantile_median
+ 0.20 × ElasticNet_rank
```

LightGBM负责非线性和交互，Elastic Net是稳定、可解释基线。暂不采用深度神经网络：两年数据、季度基本面和约 5,000 只股票不足以证明其稳定优势；只有样本外连续八个季度显著胜出才可作为 Challenger，但不能直接替换模型家族。

### B5.3 固定特征组与组内预算

| 特征组 | 最大贡献预算 |
|---|---:|
| 企业质量/现金流/治理 | 25% |
| 成长和预期变化 | 25% |
| 估值 | 20% |
| 行业景气 | 15% |
| 市场/价格/流动性 | 10% |
| 事件和叙事 | 5% |

使用单调约束：治理风险、估值昂贵、拥挤、流动性风险不得在其他条件不变时提高预测；质量、现金流可信度不得在其他条件不变时降低长期预测。SHAP 只做归因，不把 SHAP 当因果证据。

### B5.4 训练规范

- Expanding + rolling 双窗口；最近 5 年加权更高，但保留完整历史压力期。
- Purged walk-forward，标签重叠区执行 embargo。
- 每季度重训；月度只校准，不重搜超参数。
- 超参数每年最多搜索一次，搜索空间固定并记录试验总数。
- 行业、市值和流动性分层采样；退市股票保留。
- 输出分位数 `q10/q50/q90`，而不是单点收益。

## B6. 财务质量、异常与盈利预测

### B6.1 财务评分固定为三层

```text
第一层：会计和业务规则硬检查
第二层：同行 Robust Z-score / 历史分位
第三层：Isolation Forest 异常提示
```

Isolation Forest 只发现“不寻常”，不判断好坏。异常分 ≥95 分位时触发人工/规则复核，不能直接扣分。

### B6.2 盈利预测

固定采用分位数 LightGBM，分别预测下一季度营收、扣非利润、毛利率和经营现金流的 q10/q50/q90。输入包括历史财务、行业因子、价格/销量、公司指引、季节性和公告事件。

```text
forecast_final =
  confidence_model × model_forecast
+ confidence_consensus × consensus_forecast
+ confidence_rule × seasonal_rule_forecast
```

三项置信度归一化。没有一致预期时，其权重为 0，而不是填 0 值。超预期按实际值落在预测分布中的分位计算。

## B7. 公告事件：结构化抽取 + 影响模型 + 生存模型

### B7.1 固定处理链

```text
官方原文
→ 文档/OCR解析
→ LLM结构化字段抽取
→ 规则一致性验证
→ 事件分类模型
→ 影响幅度和持续期模型
→ 投资逻辑状态机
```

### B7.2 固定输出

事件分类模型采用 Gradient Boosting，输出方向概率、严重度、影响维度和 5/20/63 日影响分布。事件持续性采用 Cox proportional hazards 或离散时间生存模型，估计事件影响仍然有效的概率：

```text
effective_impact(t) = materiality × direction_probability
                    × survival_probability(t)
                    × evidence_confidence
```

立案、审计、债务、控制权事件不走普通衰减，由状态机明确解除；合同、回购计划和主题催化按执行进度更新生存概率。

## B8. 主题叙事：动态聚类 + 知识图谱 + 扩散图

### B8.1 主题发现

固定使用：中文金融向量模型生成文本嵌入，HDBSCAN 做增量主题聚类，时间窗口为 7/30/90 日；BERTopic 类 c-TF-IDF 只负责主题词解释。聚类模型发现候选主题，不能直接形成交易主题。

### B8.2 主题确认

```text
theme_confirmation =
  0.20 × official_source
+ 0.20 × cross_source_growth
+ 0.15 × company_breadth
+ 0.15 × price_breadth
+ 0.15 × capital_persistence
+ 0.15 × fundamental_verifiability
- crowding_penalty
```

必须同时满足：至少 2 类独立来源、至少 5 个真实关联公司或明确窄行业、连续 3 个交易日证据、非单一自媒体传播。BOCPD检测叙事强度突变，图传播模型监控从媒体→产业→公司→价格的扩散。

### B8.3 公司映射

知识图谱固定保存公司—产品—客户—供应链—收入—公告证据关系。语义相似度只召回候选，最终业务暴露分由结构化证据计算。没有营收/订单/产能/官方披露证据的概念关联，业务真实性最高 40。

## B9. 波动、相关性和尾部风险

### B9.1 个股波动

生产模型固定为 GJR-GARCH(1,1) + Student-t，显式处理负收益冲击带来的不对称波动；样本不足或拟合失败时回退 EWMA（半衰期 20 日）。每日更新预测，月度重估参数。

### B9.2 协方差

正式优化使用 Ledoit-Wolf 非线性收缩协方差，禁止直接求逆样本协方差。DCC-GARCH只对指数、行业和组合主要风险因子计算动态相关性，用作危机相关性乘数，不对全市场 5,000 只股票直接拟合。

```text
Sigma_final = regime_multiplier
            × factor_covariance
            + shrunk_residual_covariance
```

### B9.3 尾部风险

固定计算历史模拟 CVaR 95% 和压力 CVaR：压力样本对 S2/S3 状态加权 2 倍。组合优化的主风险目标为 CVaR，波动率只作为辅助报告。

## B10. 观点到预期收益：Black-Litterman

研究引擎输出不能直接当收益率。固定使用 Black-Litterman 将市场/风险预算先验与 ALIS 观点融合：

```text
prior_return = risk_aversion × Sigma × benchmark_weight
view_return  = calibration(score_vector, horizon)
view_uncertainty Ω ∝ 1 / confidence²
posterior_return = BL(prior_return, view_return, Ω)
```

评分到收益的映射采用滚动等距校准或 isotonic regression；置信度越低，观点越接近先验。任何单股 126 日年化观点不得超过历史同类收益分布的 95% 分位。

## B11. 最终组合：CVaR 优化，HRP 降级

### B11.1 固定目标

```text
max  posterior_expected_return
   - 0.50 × CVaR_95
   - 0.20 × drawdown_proxy
   - transaction_cost
   - turnover_penalty
```

系数通过风险预算量纲归一后使用，不能直接混合不同单位。

### B11.2 V1固定硬约束

- 普通股票单股上限15%，高置信核心股票上限25%；首次建仓不超过目标仓位的50%，经下一次有效证据或价格条件确认后再提高。
- 单行业 ≤25%，高度相关行业合计 ≤35%。
- 单主题 ≤20%，纯叙事未验证仓位合计 ≤5%。
- 高风险股票合计 ≤5%，单只 ≤1%。
- 20 日平均成交额的参与率 ≤1%，预计 5 个交易日内可退出。
- 月度双边换手预算 ≤30%，除非触发硬风险退出。
- 任一股票对组合 CVaR 的边际贡献 ≤12%。
- S2状态权益目标仓位上限55%，S3上限70%；剩余部分允许配置货币、债券、黄金、低波动和红利ETF。连续纯现金达到3个交易日后必须生成专项解释。

### B11.3 降级顺序

```text
CVaR优化成功 → 使用优化结果
优化不可行 → 放松软换手约束一次
仍不可行 → 使用HRP风险权重并应用全部硬约束
数据不足 → 等权风险预算/保持现仓，不主动扩仓
```

严禁优化器失败后自动使用无约束均值方差结果。

## B12. 投资逻辑：贝叶斯更新 + 必要条件状态机

每条假设保存先验成立概率 `P(H)`。新证据按来源、独立性和方向生成有限的 Bayes Factor：

```text
posterior_odds = prior_odds × capped_bayes_factor
```

单条证据的 Bayes Factor 固定截断在 `[0.5, 2.0]`，避免重复新闻或LLM判断让概率瞬间极端化；同源转载只算一次。

```text
P(H) ≥ 0.75  已验证
0.55～0.75   基本成立
0.40～0.55   待验证
0.25～0.40   预警
< 0.25       证伪
```

必要条件任一证伪，整体逻辑进入证伪；充分性较低的辅助假设按加权几何平均聚合，禁止算术平均掩盖短板。

## B13. 各引擎更细的评分计算契约

所有引擎统一输出：

```json
{
  "score": 0,
  "confidence": 0.0,
  "coverage": 0.0,
  "peer_percentile": 0.0,
  "history_percentile": 0.0,
  "trend": "up|flat|down",
  "state": "engine_specific_state",
  "top_positive_evidence": [],
  "top_negative_evidence": [],
  "hard_gates": [],
  "model_version": "",
  "as_of_time": "",
  "available_time": ""
}
```

引擎基础分统一公式：

```text
base = Σ(normalized_metric_i × prior_weight_i × availability_i)
       / Σ(prior_weight_i × availability_i)

score = clamp(
    base
  + trend_adjustment[-10,+10]
  + cross_evidence_adjustment[-5,+5]
  - risk_penalty[0,30],
  0, 100
)
```

缺失指标会降低 coverage 和 confidence，不允许通过重新归一化假装数据完整。若核心指标缺失，即使数值分高，也按 A2 门槛限制使用。

### B13.1 企业质量的硬细则

- ROIC使用 NOPAT/投入资本，租赁负债和资本化研发按行业模板调整。
- ROE必须拆成利润率、周转率和杠杆，杠杆驱动的高ROE不得满分。
- 经营现金流/净利润使用滚动四季度和三年中位数双口径。
- 商誉、应收、存货增长超过收入增长 20 个百分点时触发质量复核。
- 质量分采用加权几何平均，任一“现金转化/资产安全”低于30时总分最高60。

### B13.2 成长与预期的硬细则

- 收入、扣非利润、每股指标同时计算，防止增发带来的总量假增长。
- 同比、环比、两年复合和季度加速度同时存在；季度季节性用同期模型处理。
- 预期修正看幅度、覆盖分析师比例和连续方向；单家机构修改不得代表一致预期。
- 实际超预期以预测分布位置衡量，不用简单 `(实际/预期-1)` 处理接近零或亏损值。

### B13.3 估值的硬细则

- 基准安全边际：稳定企业 ≥20%，成长企业 ≥30%，周期/高不确定企业 ≥40%。
- S1/S2/S3 分别乘以 1.10/1.35/1.25。
- DCF必须进行营收、利润率、资本开支、折现率、永续增长五维敏感性分析。
- 乐观情景不能用于开仓门槛，只能用于收益空间展示；开仓用悲观与基准加权价值。

### B13.4 情绪和叙事的硬细则

- 情绪窗口固定 5/20/60 日，短窗口影响入场，长窗口影响拥挤。
- 主题分至少 20% 来自基本面可验证性；没有验证时主题贡献上限为总入场分的 3 分。
- 进入拥挤状态后，即使价格继续上涨，也只降低仓位或保持，不因热度继续加分。
- 退潮后需重新出现官方催化、宽度和资金三项确认，不能只因一次反弹恢复。

## B15. 模型上线的硬指标

### 预测模型

- 样本外 Rank IC 为正且在至少 60% 的滚动季度为正。
- 相对 Elastic Net 基线的信息系数提升 ≥10%，或尾部风险明显下降。
- 校准后各预测分位实际覆盖误差 ≤5 个百分点。
- 扣成本后仍有经济意义，且不由单一年度或行业贡献超过 40%。

### 状态模型

- 平均状态驻留期符合业务含义，不得高频日内翻转。
- 状态间波动、宽度、流动性至少两项具有稳定区分度。
- 后验预测检验通过；压力状态对历史主要风险期有合理召回。
- 状态门控相对无门控基线降低样本外最大回撤或CVaR，且不过度牺牲长期收益。

### 组合模型

- 约束满足率 100%。
- 换手、成本和流动性冲击纳入回测。
- 相对等权和HRP基线，风险调整结果在多数窗口不劣。
- 优化失败率 <1%；所有失败均有日志和确定性降级结果。

## B16. 明确禁止的设计

- 禁止让一个大模型阅读全部资料后直接输出总分和仓位。
- 禁止强化学习直接管理真实组合；其奖励函数和状态漂移风险暂不适合本系统。
- 禁止用普通 HMM 同时承担突变检测、行业周期、个股预测和仓位优化。
- 禁止用样本内收益选择状态数、模型和权重。
- 禁止频繁自动搜索超参数并把最佳回测结果上线。
- 禁止未来数据修订覆盖当时决策快照。
- 禁止“空数据按0分”“模型失败沿用旧高分”“来源转载按多条证据”。
- 禁止因主题热度或技术强势绕开治理、财务和估值门控。

## B17. 本模型栈的主要金融研究依据

- [Ang 与 Timmermann：Regime Changes and Financial Markets](https://www.nber.org/papers/w17182)：状态切换可刻画金融序列均值、波动、相关性和风险收益关系的结构变化。
- [Maruotti、Punzo、Bagnato：Hidden Markov and Semi-Markov Models for Daily Returns](https://doi.org/10.1093/jjfinec/nby019)：金融收益的肥尾分布与半马尔可夫状态持续期建模依据。
- [Adams 与 MacKay：Bayesian Online Changepoint Detection](https://arxiv.org/abs/0710.3742)：在线计算当前运行长度与突变概率。
- [Engle 与 Sheppard：DCC-GARCH](https://www.nber.org/papers/w8554)：动态条件相关和大规模时变协方差的经典框架。
- [Ledoit 与 Wolf：Nonlinear Shrinkage](https://doi.org/10.2139/ssrn.2383361)：降低高维样本协方差噪声和组合不稳定性。
- [López de Prado：Hierarchical Risk Parity](https://doi.org/10.3905/jpm.2016.42.4.059)：提供不依赖协方差矩阵求逆的分散风险基线。
- [Gu、Kelly、Xiu：Empirical Asset Pricing via Machine Learning](https://www.nber.org/papers/w25398)：树模型和非线性交互在横截面资产定价中的研究依据。

固定模型栈的目标不是宣称某个模型永远有效，而是防止研发过程中随意换模型、重复试验和追逐样本内结果。系统通过固定模型职责、允许参数重估、保留透明基线和严格样本外晋升来适应市场变化。

## C1. 决议等级

计划书中的条目统一归为三类：

```text
R：有论文、标准或官方文档支撑的方法决议
E：在约束条件下作出的 V1 工程决议
P：法规、数据许可、成本等外部条件决定的产品边界
```

R不表示论文保证收益；E不伪装成学术结论。三类都属于实施基线，开发者不得现场换方案。需要改变时必须提交ADR，说明原决议、证据、兼容性、迁移、回滚和重新验证结果。

## C2. 固定数据架构

| 编号 | 决议 | 类型 | 实现细则 | 依据 |
|---|---|---|---|---|
| DATA-01 | 四层数据结构固定为 Raw、Clean、Feature、Decision | E | 层间只通过版本化任务推进；Raw不可原地修改 | 可追溯、可重放和点时回测需求 |

| DATA-03 | 数据质量固定检查八个维度 | R | schema、completeness、uniqueness、validity、integrity、freshness、volume、distribution | Great Expectations官方质量维度 |

| DATA-05 | Parquet为历史分析冷存储 | R/E | 按数据域/年份/月分区；ZSTD压缩；禁止大量小文件；manifest登记hash和schema | Apache Parquet列式格式与压缩规范 |

| DATA-07 | Redis不得成为事实数据库 | E | 仅缓存、Streams、状态、限流和短租约锁；任何最终结果必须落PostgreSQL | Redis内存数据结构和持久性边界 |

### C2.1 PostgreSQL固定表策略

- 日线、因子、事件快照按 `trade_date/available_time` 做范围分区；仅在分区裁剪能减少扫描时建分区。
- 核心业务字段使用关系列；不确定扩展字段才使用JSONB，禁止整行塞进JSONB。
- 仪表盘重查询使用预计算表或物化视图；刷新任务有版本和完成标志。
- 唯一约束必须包含业务键与版本键；幂等写采用 `INSERT ... ON CONFLICT`。
- 线上查询必须有 `EXPLAIN ANALYZE` 基线；P95目标：详情API≤300ms、列表≤800ms、复杂研究查询≤3s。
- 备份固定为每日全量/基础备份加连续WAL归档；每季度做一次恢复演练。

官方依据：[PostgreSQL分区文档](https://www.postgresql.org/docs/current/ddl-partitioning.html)、[JSON类型文档](https://www.postgresql.org/docs/current/datatype-json.html)、[物化视图文档](https://www.postgresql.org/docs/current/rules-materializedviews.html)。

### C2.2 Redis固定用途

任务队列采用 Redis Streams consumer group，不采用Pub/Sub承载必须处理的任务。每个消息必须包含 `job_id`、`idempotency_key`、`attempt`、`trace_id`、`created_at`。处理成功后ACK；超时消息由pending巡检重新认领；超过最大次数进入PostgreSQL失败队列。

锁固定采用带随机token和TTL的租约；释放时必须校验token。锁只防重复执行，不用于保证金融事实一致性，事实一致性由数据库唯一约束和事务保证。Redis官方说明Streams支持持久化、回放与消费者跟踪，而Pub/Sub是即时丢弃式传输：[Redis Streams](https://redis.io/docs/latest/develop/data-types/streams/)、[Redis分布式锁](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。

## C3. 固定采集与补全协议

### C3.1 数据源顺序

```text
L0 交易所、巨潮、统计局、央行等官方披露
L1 Tushare结构化接口
L2 已验证的网页/公开API备用源
L3 OCR/文档抽取
L4 人工录入与人工确认
```

低级别来源不得静默覆盖高级别来源。冲突时保存全部版本，以来源级别、发布时间和字段规则生成正式值，并保留冲突记录。

### C3.2 请求协议

- 所有远程调用必须有连接超时、读取超时和总时限。
- 重试固定为指数退避加full jitter，默认最多5次：`1s、2s、4s、8s、16s`上限随机化。
- 429、连接重置、网关5xx、临时DNS失败可重试；401/403、参数错误、schema错误不可盲目重试。
- 空结果先按业务语义分类：确认无数据、暂未发布、权限伪空、源异常伪空。只有带覆盖证明的“确认无数据”可以成功结束。
- 所有写操作必须有幂等键；不具备幂等性的远程动作禁止自动重试。
- 对同一上游只在采集边界重试一次，禁止API层、任务层和worker层叠加重试造成放大。

AWS关于超时、幂等、限制重试以及指数退避加抖动的工程依据见[Timeouts, retries and backoff with jitter](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)和[Exponential Backoff and Jitter](https://aws.amazon.com/blogs/architecture/exponential-backoff-and-jitter/)。

### C3.3 并发固定规则

- Tushare全局并发初值2，每接口独立令牌桶；网页源单域名并发2。
- 并发控制器每5分钟根据429率、P95延迟和成功率调整一次，范围1～8。
- 429率>2%或P95较基线翻倍时并发减半；连续30分钟稳定且失败率<0.5%才增加1。
- 财务、股东等按股票调用的接口必须小批次提交，每批50条只是提交粒度，不是一次任务上限；任务持续运行至缺口清零。
- OCR为CPU/内存隔离队列，并发固定为 `max(1, CPU核数/2)`，不得与在线API争抢worker。

这些数值是E类工程决议，先固定运行，再根据真实限流指标通过ADR调整。

## C4. 固定后端和部署架构

### C4.1 应用边界

V1固定为两个独立但同语言的运行单元：

```text
React + TypeScript + Vite 前端
Python 3.11 + FastAPI 模块化单体（唯一业务后端）
SQLAlchemy 2 + Alembic + Pydantic 2 + asyncpg
Polars/Pandas + NumPy/SciPy + statsmodels + scikit-learn + LightGBM
Python独立worker进程（与API同一代码库、同一依赖环境、不同进程）
PostgreSQL + Redis + MinIO + Parquet
本地由项目启动脚本直接启动Uvicorn、worker和Vite
```

运行单元固定为：

```text
主量化系统：8000 FastAPI + 5173 React前端
独立数据中台：8100 FastAPI + 5174 技术前端
```

数据中台可以被主后端代理访问，但数据库迁移、任务、日志和前端仍保持独立；统一的是Python版本、依赖原则和数据契约，不是把两个服务强行合并。

FastAPI内部固定按领域模块划分：data_asset、ingestion、quality、market、fundamental、industry、event、narrative、thesis、valuation、portfolio、model_registry、job。模块不得跨层直接访问对方内部表，通过service接口或领域事件协作。

统一语言边界：后端生产代码、采集器、调度器、任务worker、数据清洗、模型训练、模型推理、回测和组合优化全部使用Python。不得新建Node/NestJS/Express服务。Node.js仅作为React/Vite工具链运行时，不承载业务API、定时任务或数据处理。

本地固定启动方式：

```text
./scripts/start_backend.sh   # uvicorn启动FastAPI
./scripts/start_worker.sh    # Python Redis Streams worker
npm run dev                 # Vite前端开发服务
```

当前阶段不使用Docker Compose和Nginx。两个FastAPI服务分别直接监听8000/8100，两个Vite前端分别监听5173/5174；PostgreSQL、Redis和MinIO使用本机已有服务。云服务器部署方式在迁移阶段另建部署ADR，但不得改变“Python + FastAPI服务边界”的技术要求。

AWS架构指导强调先明确业务能力和子域边界，微服务同时引入部署、网络和数据一致性成本；因此当前单用户/低访问量条件下采用模块化单体属于E类决议，而不是待选建议：[AWS工作负载分段指导](https://docs.aws.amazon.com/wellarchitected/latest/framework/rel_service_architecture_monolith_soa_microservice.html)。

### C4.2 微服务拆分硬门槛

只有某模块同时满足以下四项才允许拆分：

1. 需要独立扩缩容且资源曲线与主应用明显不同。
2. 有明确领域API，跨模块事务已消除。
3. 独立部署能解决已经测量到的可靠性或性能瓶颈。
4. 已具备集中日志、指标、追踪、配置、发布和回滚能力。

第一候选仅限OCR/文档处理或大规模模型推理；不得因代码目录变大就拆服务。

### C4.3 明确不采用

- V1不使用Kafka；Redis Streams满足当前任务量和回放需求。
- V1不使用Docker Compose、Nginx或Kubernetes；本地直接运行Python进程和Vite开发服务器。
- V1不使用ClickHouse；达到计划书三项联合门槛后才发起ADR。

## C5. 固定数据质量评分

每个数据资产建立契约，不使用泛化的“完整/部分”文字：

```text
quality_score =
  0.25 × completeness
+ 0.15 × validity
+ 0.15 × integrity
+ 0.10 × uniqueness
+ 0.10 × freshness
+ 0.10 × source_agreement
+ 0.10 × temporal_consistency
+ 0.05 × schema_stability
```

状态固定为：

```text
COMPLETE：所有必需范围达到契约，且无P0/P1质量错误
PARTIAL：明确存在缺口，必须列出缺失键和补全任务
NOT_DUE：按披露日尚不应存在，不算缺失
UNAVAILABLE：来源或权限确认不可用，已有替代路线或人工决议
BLOCKED：无可执行路线，需要外部权限/数据源/产品决策
```

“已有483个开市日，约等于500”不得标COMPLETE。交易日历完整性按目标起止日期、交易所官方日历和逐日键集合判断，不按近似数量判断。补全完成后不因重启重新显示PARTIAL；只有新的契约缺口被检测到才改变状态。

数据质量维度依据[Great Expectations官方质量用例](https://docs.greatexpectations.io/docs/reference/learn/data_quality_use_cases/dq_use_cases_lp/)，但ALIS使用自有SQL/规则实现，V1不引入Great Expectations运行时依赖。

## C6. 固定前视偏差防线

- 所有财务、公告、宏观和文本保存 `report_period`、`publish_time`、`available_time`、`ingestion_time`、`revision_version`。
- 回测数据访问层只暴露 `as_of(decision_time)`，业务代码不得绕过。
- 指数成分、ST状态、股票名称、行业分类和停复牌必须使用历史版本。
- LLM历史回测只允许读取当时文本；不得让已知后续结果进入提示词。通用LLM自身可能含有未来知识，因此历史文本判断只验证抽取能力，不把其自由推理收益作为可信回测结果。
- 每次模型数据集生成保存SQL、manifest、最大available_time和hash。

这项决议由金融模型验证中的前视偏差要求以及点时语言模型研究支持：[CFA Institute模型验证](https://rpc.cfainstitute.org/sites/default/files/-/media/documents/article/rf-brief/investment-model-validation.pdf)、[Scaling Point-in-Time Language Models](https://www.nber.org/papers/w35247)。

## C7. 固定LLM与OCR边界

### C7.1 OCR

- PDF有文本层时固定优先解析文本层，不做OCR。
- 扫描件才进入OCR；OCR结果保存页码、坐标和置信度。
- 数字、日期、比例、证券代码必须经正则、表格结构和原文图像三重校验。
- OCR置信度<0.90的关键数字不得自动进入正式字段。

### C7.2 LLM

- 输入必须附来源、发布时间、页码/段落和文档hash。
- 输出只接受固定JSON Schema；temperature固定0或模型允许的最低确定性档。
- 每个结论必须引用证据span；没有证据时输出unknown。
- 关键数字由确定性解析器复核；事件方向由规则和小模型二次校验。
- LLM失败、超时或schema不合格时进入重试/人工队列，绝不沿用旧结论冒充最新结果。
- 模型升级前必须在冻结的公告、财报、质押、监管和合同测试集上重新验收。

## C8. 固定前端产品语义

- “完整”只能对应C5的COMPLETE。
- 进度分母来自确定的数据契约键集合，不允许用估算数冒充精确分母。
- 实时日志固定显示时间、数据源、接口、请求对象、业务键、批次、结果行数、重试和错误分类。
- 单次补全按钮创建一个持续到缺口清零的父任务；50只等批次只在子任务日志出现，不向用户表述为任务上限。
- 阻塞数只统计BLOCKED，不把重试中、NOT_DUE、已配置替代源或人工复核混入。
- 页面必须能下钻到缺失业务键、来源响应摘要、最后成功时间和下一步动作。

## C9. 固定安全、密钥和许可规则

- Tushare token、数据库口令和模型密钥只通过环境变量/Secret注入，不入库、不入日志、不进前端。
- 原始网页、公告和研报保存前记录来源URL、抓取时间、许可/使用边界和hash。
- 交易所/官方数据为事实优先源，但抓取频率仍遵守站点规则；需要登录、绕过验证码或规避访问控制的数据源不得自动化绕过。
- 任何替代源上线前必须通过字段映射、历史抽样、时效、稳定性和许可五项验收。

## C10. 固定可观测性与SLO

| 对象 | 指标与V1目标 |
|---|---|
| 数据任务 | 成功率≥99%，失败100%进入可重放队列 |
| 数据新鲜度 | 日线在预定窗口后60分钟内完成；公告发现延迟P95≤15分钟 |
| API | 可用性≥99.5%，详情P95≤300ms，列表P95≤800ms |
| 任务状态 | Redis与PostgreSQL最终一致，状态丢失率为0 |
| 模型推理 | 每次输出均有版本、置信度和证据，登记率100% |
| 组合约束 | 生成结果与模拟成交后持仓的约束违反率均为0 |
| 模拟执行 | 信号、订单、成交、滑点、费用和持仓账本登记率100% |
| 恢复 | RPO≤15分钟，RTO≤4小时；季度恢复演练 |

告警固定分三级：P0数据写错/组合约束破坏立即暂停；P1核心源或任务持续失败通知并降级；P2延迟和单源差异进入工作队列。
